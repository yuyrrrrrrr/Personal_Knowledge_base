## 1. 性能分析

```python
import cProfile

cProfile.run("slow_function()")
```

- 优化前必须测量，不能只凭直觉判断瓶颈。
- `timeit` 适合比较小段代码的执行时间。
- `cProfile` 可以查看函数调用次数和累计耗时。
- `tracemalloc` 可以追踪 Python 内存分配。
- `py-spy`、`line_profiler` 等工具可以分析运行中程序或热点行。
- 优先优化耗时占比最高、调用频率最高的部分。

## 2. 时间复杂度与数据结构

- 算法复杂度通常比局部语法优化影响更大。
- 列表按索引访问很快，但频繁在头部插入删除效率较低。
- 字典和集合的平均成员查询复杂度通常为 `O(1)`，适合去重和查找。
- `deque` 适合两端频繁插入和删除。
- 排序通常为 `O(n log n)`，应避免在循环中反复排序。
- 选择合适的数据结构往往比手写微优化更有效。

## 3. 常见代码优化

- 把循环中不变的表达式移到循环外。
- 优先使用内置函数、标准库和成熟第三方库。
- 使用生成器或迭代器减少一次性大列表。
- 使用 `join()` 拼接大量字符串，避免循环中反复 `+=`。
- 使用集合去重或判断存在性，减少嵌套循环。
- 使用推导式处理简单转换，但不要牺牲可读性。
- 缓存纯函数结果，例如 `functools.lru_cache`。
- 避免在热点路径中进行无必要的对象创建和异常处理。

## 4. I/O 与缓存优化

- 文件读写应批量处理，避免频繁打开关闭文件。
- 网络请求可使用连接池、并发请求和超时控制。
- 数据库操作应减少往返次数，避免明显的 N+1 查询。
- 缓存适合重复计算结果和稳定数据，但需要处理失效与容量。
- 内存缓存可使用字典或 `functools.lru_cache`，跨进程缓存可使用 Redis 等工具。
- 序列化大数据时应比较 JSON、二进制和列式格式的成本。

## 5. 并发与并行

- I/O 密集型任务优先考虑异步 I/O、线程池或外部服务并发能力。
- CPU 密集型任务可考虑多进程、原生扩展或专用计算库。
- Python 线程受 `GIL` 影响，不等于 CPU 任务自动并行。
- 并发会引入竞态、死锁、上下文切换和调试复杂度。
- 应限制并发数量，避免压垮数据库、磁盘或下游服务。
- 并发的正确性优先于吞吐量，必须配合测试和监控。

## 6. 内存优化

- 使用生成器按需产生数据，避免一次性加载全部内容。
- 大数据处理可使用分块读取和流式计算。
- `__slots__` 可以减少实例对象的内存开销。
- 避免无意义复制，理解浅拷贝和深拷贝差异。
- 及时释放不再使用的引用，避免循环引用造成长期占用。
- `weakref` 适合建立不阻止垃圾回收的引用关系。
- 内存优化应结合 `tracemalloc` 等工具确认实际占用。

## 7. 性能测试与优化原则

- 建立可重复的基准测试，记录 Python 版本、硬件和数据规模。
- 使用真实或接近真实的数据分布，避免只测试理想输入。
- 同时关注平均耗时、尾延迟、吞吐量和资源占用。
- 优化后重新测量，确认收益并检查是否引入回归。
- 不为尚未出现的性能问题预先增加复杂架构。
- 性能、可读性和可维护性需要权衡，优先保证正确性。
