# Python 进阶学习总结

## 进阶应用（第1-6章）

### 1-Functional Programming

- 使用 `def` 定义函数，通过 `return` 返回结果，并保持函数职责单一、命名清晰。
- 支持位置参数、关键字参数、默认参数、`*args`、`**kwargs` 以及仅位置或仅关键字参数。
- 理解 `LEGB` 作用域、`global`、`nonlocal` 和闭包，避免可变默认参数陷阱。
- `lambda` 适合短小表达式，函数可以赋值、传参和返回，体现一等对象与高阶函数思想。
- 装饰器通过包装函数增加日志、计时、缓存和权限等功能，并使用 `functools.wraps` 保留元数据。

### 2-Modules and Packages

- 模块是组织代码和隔离命名空间的 `.py` 文件，导入时顶层代码会执行。
- 常见导入方式包括 `import`、`as`、`from ... import ...`，通配符导入通常不推荐。
- 自定义模块可使用 `__all__` 控制导出，并与 `if __name__ == "__main__":` 区分直接运行和导入。
- 包通过目录和 `__init__.py` 组织模块，支持绝对导入和相对导入。
- 标准库应优先复用，第三方依赖通过虚拟环境、`pip`、`requirements.txt` 或 `pyproject.toml` 管理。

### 3-File Operations

- 使用 `open()` 读写文件时必须关注模式、编码和关闭时机，文本文件应明确使用 `UTF-8`。
- `read()`、`readline()`、`readlines()`、`write()` 和 `writelines()` 是常见文本文件操作。
- `with` 上下文管理器保证文件和其他资源在异常情况下也能正确释放。
- `pathlib` 提供跨平台路径拼接、存在性检查和目录遍历能力。
- CSV 适合表格文本，JSON 适合嵌套结构化数据；注意序列化、编码、表头和新行处理。

### 4-Exception Handing

- 使用 `try-except` 捕获可预期异常，并按具体异常类型从窄到宽处理。
- `else` 在无异常时执行，`finally` 用于必须执行的资源清理。
- 使用 `raise` 主动抛出异常，自定义异常通常继承 `Exception` 或更具体的异常类。
- 异常会沿调用链传播，`raise ... from error` 可以保留原始异常原因。
- 调试时阅读完整堆栈，结合 `breakpoint()`、`pdb`、`traceback` 和日志定位问题。

### 5-OOP (object-oriented programming)

- 类描述对象的属性和行为，实例由 `__init__()` 初始化，`self` 表示当前对象。
- 封装通过约定、属性方法和访问控制隐藏内部实现，只暴露稳定接口。
- 继承通过 `super()` 复用和扩展父类行为，需要理解 MRO 并避免过深层次。
- 多态允许不同对象响应同一调用，Python 还强调鸭子类型和协议。
- `__repr__`、`__str__`、`__len__`、`__iter__` 等特殊方法让对象接入 Python 数据模型。

### 6-Advanced Features

- 迭代器实现 `__iter__()` 和 `__next__()`，适合按需获取数据并处理一次性遍历。
- 生成器通过 `yield` 惰性产生值，适合大文件、数据流和无限序列。
- 上下文管理器统一处理资源获取与释放，可使用类协议或 `contextlib.contextmanager`。
- 线程适合 I/O 密集型任务，进程适合 CPU 密集型任务，共享状态需要同步与测试。
- `async`、`await` 和 `asyncio` 适合高并发 I/O，但不会自动解决 CPU 阻塞问题。

## Python 进阶（第7-9章）

### 7-Code Quality And Testing

- 使用 `PEP 8`、格式化、Lint 和类型注解保持代码一致、清晰、可检查。
- 单元测试验证最小行为，重点覆盖正常、边界和异常路径。
- `pytest` 通过断言、`fixture`、参数化和异常断言提高测试效率。
- Mock 适合隔离外部依赖，覆盖率是参考指标而不是唯一质量目标。
- 调试、日志、文档、重构和 CI 共同构成稳定的质量流程。

### 8-Performance Optimization Techniques

- 优化前使用 `timeit`、`cProfile`、`tracemalloc` 等工具定位真实瓶颈。
- 优先改善算法复杂度和数据结构选择，再考虑局部代码微优化。
- 利用生成器、内置函数、缓存、批量 I/O 和字符串连接优化常见性能问题。
- I/O 密集型任务可使用异步或线程，CPU 密集型任务可考虑多进程或原生扩展。
- 通过减少复制、分块处理和 `__slots__` 控制内存，并以基准测试验证收益。

### 9-Design Mode

- 设计模式是解决常见设计问题的经验，不是必须机械套用的模板。
- 创建型模式关注对象创建，结构型模式关注对象组合，行为型模式关注对象协作。
- Python 可优先使用函数、协议、鸭子类型、装饰器和上下文管理器实现 Pythonic 方案。
- 工厂、策略、观察者等模式应根据变化点和职责边界选择性使用。
- 简单实现优先，模式应提升可读性、可测试性和可维护性，避免过度设计。

9. 封装、继承和多态分别解决什么问题？
