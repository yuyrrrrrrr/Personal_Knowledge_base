## 1. 设计模式基础

- 设计模式是可复用的问题解决经验，不是必须套用的语法模板。
- 模式主要解决对象创建、结构组合和对象协作等常见问题。
- 模式应服务于代码可读性、可扩展性和可测试性。
- 过度设计会带来额外类和抽象，简单需求优先使用简单实现。
- 应先识别变化点和职责边界，再判断是否需要模式。

## 2. 创建型模式

- **工厂模式**：把对象创建逻辑集中到工厂，调用方只依赖接口。
- **抽象工厂**：创建一组相关对象，适合多产品族场景。
- **建造者模式**：分步骤构建复杂对象，降低超长构造函数复杂度。
- **单例模式**：保证一个类只有一个实例；Python 中应谨慎使用全局状态。
- **原型模式**：通过复制已有对象创建新对象。

```python
class ParserFactory:
    @staticmethod
    def create(kind):
        if kind == "json":
            return JsonParser()
        if kind == "csv":
            return CsvParser()
        raise ValueError(f"不支持的类型：{kind}")
```

## 3. 结构型模式

- **适配器模式**：把不兼容接口转换为调用方期望的接口。
- **装饰器模式**：在不修改原对象的情况下增加行为。
- **代理模式**：通过代理对象控制对目标对象的访问。
- **外观模式**：为复杂子系统提供简化入口。
- **组合模式**：用统一接口处理单个对象和对象组合。
- **桥接模式**：分离抽象与实现，减少组合维度爆炸。

## 4. 行为型模式

- **策略模式**：把可替换算法封装为独立对象或函数。
- **观察者模式**：状态变化时通知多个订阅者。
- **命令模式**：把请求封装为对象，支持排队、撤销和记录。
- **模板方法模式**：在父类定义流程骨架，由子类实现变化步骤。
- **责任链模式**：把请求沿处理链依次传递。
- **状态模式**：根据内部状态改变对象行为。

## 5. Pythonic 实现

- 一等函数可以替代大量单方法策略类。
- 协议和鸭子类型通常比复杂继承层次更灵活。
- `dataclass` 适合表达配置对象、命令和值对象。
- 装饰器语法适合实现包装、缓存、日志和权限控制。
- `functools.singledispatch` 可以实现基于类型的函数分派。
- 上下文管理器适合资源获取、释放和事务边界。
- `collections.abc`、`typing.Protocol` 可用于表达接口。

## 6. 常用模式示例

### 策略模式

```python
def calculate(price, discount_strategy):
    return discount_strategy(price)

regular = calculate(100, lambda price: price)
vip = calculate(100, lambda price: price * 0.8)
```

### 工厂模式

- 调用方通过统一入口获得对象，不直接依赖具体类。
- 适合根据配置、文件类型或环境选择实现。

### 观察者模式

- 发布者维护订阅者列表，状态变化时逐个通知。
- 事件系统、消息总线和 UI 回调都体现类似思想。

## 7. 使用原则

- 先写清晰直接的代码，再在变化真正出现时引入模式。
- 模式名称不能替代代码解释，必要时应说明使用原因。
- 优先使用语言原生能力和标准库提供的能力。
- 抽象边界应与业务职责一致，不要为未来假设制造大量接口。
- 组合通常优于复杂继承，依赖稳定接口优于直接依赖具体实现。
- 任何模式都应配套测试，避免抽象层增加后难以维护。
