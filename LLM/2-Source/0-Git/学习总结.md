# Git 学习总结

## 1-Git Basics

- 版本控制用于记录文件变化、追踪历史、比较差异和恢复旧状态，Git 是分布式版本控制系统。
- Git 安装后需要配置用户名、邮箱、默认分支、编辑器和换行符等基础选项。
- 工作区、暂存区和本地仓库构成日常操作的核心状态模型，`HEAD` 指向当前提交或分支。
- Git 对象模型由 `blob`、`tree`、`commit` 和 `tag` 等对象组成，引用负责指向对象。
- 文件具有未跟踪、已修改、已暂存和已提交等生命周期，首次提交流程为 `status`、`add`、`commit`。

## 2-Core Operations

- 使用 `git init` 创建仓库，使用 `git clone` 获取远程仓库，并理解 `.git` 目录的作用。
- `.gitignore` 用于排除依赖、构建产物、日志和敏感文件，但不会自动停止跟踪已跟踪文件。
- `git add`、`git commit` 和提交信息规范构成日常提交流程。
- `git status`、`git diff`、`git log` 和 `git show` 用于查看状态、差异和历史。
- `restore`、`reset`、`revert` 和 `reflog` 对应不同撤销与恢复场景，其中 `reset --hard` 风险最高。

## 3-Branch Management

- 分支本质是指向提交的可移动引用，适合隔离功能、修复、实验和发布准备。
- `git branch`、`git switch`、`git checkout` 用于创建、切换、查看和管理分支。
- 合并分为快进合并和三方合并，合并冲突需要理解业务语义后手动解决。
- 变基可以整理线性历史，但会重写提交哈希，共享分支通常不应随意变基。
- Feature Branch、Gitflow、GitHub Flow 和 Trunk-Based 等策略应按团队规模与发布节奏选择。

## 4-Remote Collaboration

- 远程仓库用于协作、备份和共享，`origin` 是默认远程名称。
- `fetch` 只更新远程引用，`pull` 会进一步合并或变基，`push` 上传本地提交。
- 跟踪分支记录本地分支与远程分支的对应关系，`fetch --prune` 可清理失效引用。
- 推送冲突应通过拉取、解决冲突和测试处理，避免直接使用高风险强制推送。
- 标签、Pull Request、代码审查和 Fork/Feature/Gitflow 工作流构成远程协作核心。

## 5-Advanced Features

- 轻量标签适合临时标记，附注标签适合正式版本发布，标签需要单独推送。
- `stash` 用于临时保存工作进度，支持部分储藏、恢复和保留储藏。
- 子模块在父仓库中引用独立仓库，需要分别提交子模块和父仓库指针。
- 子树把依赖内容合并到当前仓库目录，使用简单但会改变主仓库历史。
- `rev-parse`、`cat-file`、`fsck`、`gc` 等命令用于高级历史检查和仓库维护。

## 6-Tools and Platforms

- Git GUI 工具适合查看差异和处理冲突，命令行更适合自动化和精确操作。
- GitHub 提供仓库、Issue、Pull Request、Release、Actions 和权限管理等能力。
- Issue 与项目管理功能帮助记录缺陷、需求和任务状态。
- GitHub Actions 可以自动执行测试、构建、扫描和发布，Secrets 用于保护敏感凭据。
- GitLab、Bitbucket、Gitee 等平台核心模型一致，但迁移时要处理权限、CI 和分支保护。

## 7-Advanced Practice

- Git 对象数据库由 blob、tree、commit 和 tag 等对象组成，提交关系形成有向无环图。
- 引用、HEAD、远程引用和 packfile 共同支撑历史查询与传输。
- 别名、`.gitattributes`、diff/merge 工具和 Hooks 可以提升效率与质量。
- 常见故障包括推送拒绝、合并冲突、Detached HEAD、错误提交、误删分支和仓库损坏。
- 浅克隆、稀疏检出、Git LFS、提交签名和权限审计用于性能和安全管理。

## 8-Comprehensive Project Practice

- 个人项目需要完成初始化、忽略规则、分支开发、版本标签、发布文档和远程备份。
- 团队项目需要明确分支策略、提交规范、代码审查、合并规则和主分支保护。
- 开源贡献从阅读贡献指南和选择简单任务开始，通过 Fork 与 Pull Request 完成协作。
- 发布流程应包含版本号、标签、构建产物、变更日志、回滚方案和修复回并。
- CI/CD、质量门禁和复盘机制用于保证交付稳定，并持续沉淀团队规范。
