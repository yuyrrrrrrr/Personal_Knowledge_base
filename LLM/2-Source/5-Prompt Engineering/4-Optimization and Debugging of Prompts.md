## 1. 迭代优化

- 先建立基准提示词和测试样例，再开始优化。
- 每轮只修改少量变量，便于判断变化原因。
- 根据失败样例调整指令、上下文、示例、格式和约束。
- 记录版本、变更说明、测试结果和适用模型。
- 优化目标是提升任务指标，而不是让提示词看起来更长或更复杂。
- 达到稳定效果后应冻结版本，并定期用回归测试验证。

## 2. A/B 测试与参数调整

- A/B 测试使用相同输入集比较两个提示词版本或模型参数。
- 评价指标应与任务目标一致，例如准确率、格式合规率、延迟和成本。
- `temperature` 降低时通常更稳定，提高时更发散。
- `top_p` 和采样参数应一次调整一个，并记录组合结果。
- 测试样本要覆盖正常、边界、异常和对抗输入。
- 小样本结果只能作为参考，最终选择应基于统计结果和业务成本。

## 3. 提示词压缩与负面提示词

- 删除重复说明、无效礼貌语和与任务无关的背景。
- 用结构化字段替代大段重复文字，减少 Token 消耗。
- 压缩后必须重新验证，避免删除关键约束或示例。
- 负面提示词用于明确禁止项，例如不要编造、不要输出敏感信息。
- 负面约束应具体可验证，不要只写“不要出错”。
- 过多否定规则可能让模型关注错误概念，应优先使用正向行为描述。

## 4. 常见问题与解决

| 问题 | 可能原因 | 处理方向 |
|---|---|---|
| 输出不准确 | 指令模糊、资料不足、模型能力不匹配 | 补充上下文、示例和验证步骤 |
| 输出不完整 | 范围过大、长度限制、步骤遗漏 | 拆分任务、明确检查清单 |
| 输出格式错误 | 格式说明不清、缺少 Schema | 固定输出字段并增加校验 |
| 幻觉问题 | 模型补充未知事实 | 限定资料来源、要求引用和不确定说明 |
| 一致性不足 | 参数波动、上下文冲突 | 降低随机性、固定模板和版本 |
| 安全风险 | 越权、提示注入、敏感信息泄露 | 权限隔离、输入过滤和人工审核 |

## 5. 评估方法

- 准确性：结果是否符合事实、输入资料和任务要求。
- 完整性：是否覆盖所有必要字段、步骤和边界情况。
- 一致性：相同或近似输入是否产生稳定结果。
- 创造性：在发散任务中是否提供新颖且合理的方向。
- 可用性：延迟、Token 成本、稳定性和集成难度是否可接受。
- 可结合自动规则、模型评审、人工标注和业务指标评估。
- 模型评审不能完全替代人工判断，应控制评审标准和偏差。

## 6. 调试技巧

- 把复杂提示词拆成最小可复现版本。
- 单独测试指令、上下文、示例和输出格式。
- 查看中间输出，定位错误发生在哪一步。
- 对比不同模型、参数和提示词版本的差异。
- 修改提示后重新运行完整测试集，避免只修复单个样例。
- 保留失败输入、模型输出、参数和环境信息。

## 7. 安全与可靠性

- 防范提示注入、越权工具调用、数据泄露和输出执行风险。
- 用户输入与系统指令分层，不能直接覆盖安全规则。
- 敏感数据应脱敏、加密或保留在可信环境。
- 输出进入代码执行、数据库、Shell 或网络请求前必须校验。
- 高风险操作需要权限控制、审计日志和人工确认。
- 建立降级、重试、超时和失败回退机制，避免模型不稳定影响业务。
