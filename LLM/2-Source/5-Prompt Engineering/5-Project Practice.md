## 1. 项目选题与需求

- 选择边界清晰、可验证且能体现提示词工程价值的实际任务。
- 明确目标用户、使用场景、输入来源、输出形式和成功标准。
- 区分模型适合处理的部分与必须由规则、数据库或人工完成的部分。
- 评估数据隐私、权限、合规和高风险错误成本。
- 优先使用小范围可验证的项目验证价值，再扩展功能。
- 记录不做什么和暂不支持的能力，避免需求无限扩张。

## 2. 提示词工程设计流程

1. 收集真实输入和期望输出，建立开发样本集。
2. 编写基线提示词，明确角色、任务、上下文、输入和输出。
3. 选择合适模型、参数和结构化输出方案。
4. 设计自动校验、异常处理和失败重试。
5. 运行评估集，分析错误类型和成本。
6. 迭代提示词、示例、参数和流程拆分。
7. 冻结版本并建立回归测试。

```text
系统约束 -> 任务指令 -> 输入数据 -> 输出 Schema -> 校验规则 -> 失败处理
```

- 系统指令负责安全和全局规则，用户输入不能覆盖。
- 复杂任务可拆成提取、分析、生成、校验多个步骤。
- 项目中的应用代码负责权限、校验、重试、日志和持久化。

## 3. 推荐项目方向

- 文档问答：基于个人或企业资料进行检索增强问答，并输出引用。
- 内容助手：根据主题、受众和风格生成文章、摘要和社媒文案。
- 代码助手：完成代码解释、审查、测试生成和 Bug 修复建议。
- 数据分析助手：对结构化数据做清洗说明、趋势总结和异常发现。
- 客服助手：基于知识库回答常见问题，并在越界时转人工。
- 学习辅导：根据用户水平生成讲解、练习题和反馈。
- 多步骤 Agent：把搜索、提取、计算、生成和审查连接为工作流。
- 推荐项目应包含真实评估集、错误分析、成本分析和可运行界面。

## 4. 评估与迭代

- 为项目建立人工标准和可自动计算的指标。
- 准确类任务关注正确率和事实依据，生成类任务关注完整性、相关性和可用性。
- 结构化任务关注解析成功率、字段完整率和格式合规率。
- 对话系统关注多轮一致性、任务完成率和升级人工的准确性。
- 记录每次调用的输入长度、输出长度、延迟、成本和失败原因。
- 通过错误分类定位是提示词、模型、数据还是应用流程问题。
- 迭代后必须运行回归集，避免修复一个问题引入其他回归。

## 5. 交付与复盘

- 交付内容应包含可运行程序、提示词模板、配置、测试数据和使用说明。
- 提示词版本、模型版本和参数应可追踪。
- 日志中不得记录完整敏感输入和密钥。
- 上线前完成权限、安全、异常、成本和性能检查。
- 上线后监控质量、延迟、错误率、用户反馈和成本变化。
- 复盘应总结有效模式、失败边界、改进项和下一阶段计划。
- 项目完成后沉淀可复用模板、评估集和工程规范。
