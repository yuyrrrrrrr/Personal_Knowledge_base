 ## 从翻译架构走向通用预训练
2017 年，Google 在《Attention Is All You Need》中提出 Transformer，用自注意力建模序列关系，解决 RNN 训练过程前后之间循环依赖的问题，让模型可以并行训练，这让研究者看到了它更大的潜力。
> Transformer 是为机器翻译设计的，那么应该怎样调整、训练，才能让模型服务于更多 NLP 任务？
![](Pasted%20image%2020261108151547.png)
GPT · DECODER-ONLY
自回归语言建模，预测下一个 Token。
BERT · ENCODER-ONLY
双向上下文，学习可迁移的语言表示。
T5 · ENCODER-DECODER
把所有任务统一为 Text-to-Text。

## GPT 与 BERT：预训练成为共同基础

Transformer 提供了适合大规模训练的架构。**GPT 与 BERT 把已有的预训练思路与它结合**，推动“先从海量文本学习语言，再适配具体任务”成为 NLP 的重要范式。
![](Pasted%20image%2020261108151804.png)
此前，文本分类、实体识别和阅读理解通常各自准备标注数据、设计网络并训练，基础语言能力很难共享。预训练让模型先从无标注文本中学习通用规律，再用下游任务数据适配，减少每个任务从头学习语言的负担。
## GPT-1: 预训练 + 微调两阶段

2018 年 6 月发布的 GPT-1 采用两阶段训练，把从海量文本学到的能力迁移到具体任务上。

① 预训练  
在无标注文本上预测下一个 Token，在这个过程中学习词义、句法和语义关系。

② 微调 FINE-TUNING  
用有标注的任务数据微调，把预训练能力迁移到文本分类、问答、自然语言推断等任务。

> 先学通用语言规律，再迁移到具体任务——这套两阶段思路成为后续研究的共同起点。

## BERT：用双向上下文学习语言表示
GPT-1 展示了“预训练 + 微调”的效果，从左到右预测下一个 Token，每个位置只利用前面生成的内容。几个月后发布的 BERT 使用了不同的思路：在预训练时同时利用词语左右两侧的上下文，让模型学到更适合理解任务的表示。
![](Pasted%20image%2020261108152413.png)
BERT 采用 Transformer Encoder，通过掩码语言建模（MLM）遮住部分 Token，让模型根据左右上下文恢复原文。
> 我去银行办理了 [MASK] 业务。
预测被遮住的内容时，可同时参考前面的“银行”和后面的“业务”。这种双向建模适合需要综合理解整段输入的任务。

## BERT: 让理解任务共享预训练表示
![](Pasted%20image%2020261108153136.png)

| 下游任务 | 增加的输出结构 | 预测结果 |
| :--- | :--- | :--- |
| 文本分类 | 分类头 | 文本所属的类别 |
| 命名实体识别 | Token 分类头 | 各位置的实体标签 |
| 抽取式阅读理解 | 答案位置预测头 | 答案的起止位置 |
---
**底部结论文字：**
BERT 证明同一个预训练 Encoder 可以成为多种理解任务的共同基础。针对下游任务，添加任务头并微调即可适配。它在多项语言理解评测上的表现，也推动了“预训练 + 微调”成为当时的主流范式。
但微调后，各任务模型仍需分别维护，输出结构也不同。
## T5：把所有任务统一为文本到文本
2019 年 Google 提出 T5 (Text-to-Text Transfer Transformer)，用完整的 Encoder-Decoder 把分类、翻译、摘要、问答都变成“文本输入 $\to$ 文本输出”，通过同一种生成机制完成。
```text
输入：sst2 sentence: This movie is great.
输出：positive
输入：translate English to German: The house is wonderful.
输出：Das Haus ist wunderbar.
```
![](Pasted%20image%2020261108153350.png)
## T5: 统一任务接口与预训练研究

**统一任务接口**
BERT 让任务共享预训练表示，但不同任务仍要设计各自的任务头。T5 把**任务前缀写进输入**，让分类、翻译、摘要等任务都用同一个 Encoder-Decoder 生成文本。

**系统研究预训练**
T5 用大规模消融实验比较训练目标、模型结构、数据处理和迁移策略，还构建了清洗过的大规模语料 C4，为后续研究提供了重要的实验基准。

> 从 BERT 的“共享预训练表示”，到 T5 的“统一文本接口”，**任务类型开始由输入文本表达**。这一思路也影响了后来的 Prompt Engineering 与 Instruction Tuning。

## GPT-2: 用上下文直接表达任务
BERT 让不同任务共享预训练表示，T5 统一了文本输入输出。GPT-2 则开辟出**不为任务单独微调，只靠上下文告诉模型当前要做什么**的一条新路。它先在海量文本上学习预测下一个 Token，使用时保持参数不变。摘要标记、语言标签或问答格式成为提示，让同一个模型以续写方式尝试完成不同任务。这就是零样本任务迁移 (Zero-shot Task Transfer)。
![](Pasted%20image%2020261108153744.png)
*   **摘要**：文末加 `TL;DR:`，引导续写简短总结。
*   **翻译**：输入 `English: I love you. French:`，提示生成法语。
*   **阅读理解**：先给文本，再接 `Q: ... A:`，引导续写答案。
## GPT-2 的两个关键选择

**① 坚持 DECODER-ONLY**
用因果注意力从左到右自回归生成。分类标签、译文、摘要、答案都由同一个模型逐步生成。

**② 继续扩大规模**
参数量扩到约 15 亿 (1.5B)，约为 BERT-Large 的 4.4 倍。规模增大，多项任务的零样本表现随之改善。

> 模型始终在预测下一个 Token，而上下文决定了这次续写是在做摘要、翻译，还是回答问题。

## Scaling Law: 扩规模的收益可估算
更大的模型意味着更多数据、算力和训练时间。2020 年 OpenAI 研究了参数量、数据量、计算量与语言建模损失的关系。
当其他条件不构成瓶颈时，增加任一投入，损失会按较稳定的幂律趋势下降——这就是 Scaling Law。
> 先做小规模实验拟合规律，再估计更大规模的结果，据此规划模型大小、数据与算力预算。

![](Pasted%20image%2020261108153954.png)
对企业和投资人而言，Scaling Law 让追加算力和数据可能带来的模型改进有了估算依据，降低了持续投入大模型的不确定性。

## GPT-3: 用上下文中的示例适配任务
GPT-2 已经尝试不微调的零样本任务迁移：用提示告诉模型要做什么。GPT-3 沿同一条路线，把参数量扩大到 175B，并系统比较零样本（任务描述与输入）、单样本（一个示例）和少样本（几个示例）。**两者都不更新参数**，GPT-3 进一步展示了模型如何从示例中识别任务模式与输出格式。
![](Pasted%20image%2020261108154118.png)
**示例指定任务与输出格式**
左图先给出“apple $\to$ 苹果”，“banana $\to$ 香蕉”，再以“英语：orange，中文：”结尾。模型由此识别当前任务是**英译中**，答案要沿用相同的格式。
于是它续写“橙子”。翻译能力主要来自预训练，示例负责说明**此刻要做什么、怎样回答**。这种在参数不变时根据输入示例完成任务的方式，就是上下文学习（In-context Learning）。
## 微调 vs 上下文学习

| | Fine-tuning | In-context Learning |
| :--- | :--- | :--- |
| 示例的用途 | 作为训练数据 | 作为当前输入的一部分 |
| 是否更新参数 | 是 | 否 |
| 适配结果保留在 | 更新后的模型参数中 | 当前上下文中 |
| 切换任务的方式 | 训练或加载适配后的模型 | 更换任务描述和示例 |

上下文学习让开发者遇到新任务时，先更换任务说明和示例，用同一个模型立即试做。不用先准备标注数据和微调专用模型，就能快速验证效果、降低前期成本。效果不够时，再决定是否训练。
## 从 Prompt 到 Context Engineering

GPT-3 展示了任务说明和示例可以放进上下文。选哪些示例、怎样描述要求与输出格式，都会影响结果，Prompt Engineering 因而成为使用通用语言模型的重要方法。

> 2022 年底，基于 GPT-3.5 的 ChatGPT 让更多人直接用对话写文章、改代码、解释知识。自然语言成为调用模型能力的入口。

AGENT · CONTEXT ENGINEERING

**Context Engineering** 本质上也是在控制交给模型的提示词：模型每次行动前，究竟能看到哪些任务目标、资料、工具说明、历史动作和最新结果。

Agent 要连续执行，提示词就要随任务进展更新。检索新信息、压缩旧记录，把当下最有用的内容交给模型，才能让它接着前一步决定下一步。
## Decoder-only 为什么成为主流？

Transformer 论文之后，模型沿着不同路线发展：BERT 用 Encoder-only 学习双向表示，T5 用 Encoder-Decoder 统一文本任务，GPT 则沿 Decoder-only 路线自回归生成。

三条路线各有所长。走到通用生成式大模型阶段，**看似最简单的 Decoder-only 反而成为主流**。原因可以从三个方面理解：

**① 训练样本容易构造**
自回归目标，让大量连续文本直接成为训练数据。

**② 上下文切换任务**
任务写进同一序列，靠续写直接给出答案。

**③ 结构简单统一**
同一套网络与参数，便于工程优化与规模扩展。

## ① 训练样本容易构造

大规模预训练首先要解决一个问题：如何从没有人工标注的文本中构造学习信号？

> **BERT / T5 的局限**
> BERT 预测被遮蔽的 Token，T5 生成缺失的文本片段，都是**填空式**预训练目标。面对开放式生成任务，训练时的填空与使用时的续写**并不完全一致**。

GPT 的自回归目标简洁得多——根据前文预测下一个 Token，带来几个天然优势：

*   **信号更密集**
    长度为 \(N\) 的文本，多个位置都能产生预测监督，无需构造掩码或片段破坏规则。

*   **数据形式统一**
    网页、书籍、代码、对话，只要是连续文本，都能套用同一目标训练。

*   **目标直接对齐**
    预训练学习根据前文续写，与开放式生成的使用方式直接对齐。

## ② 通过上下文切换任务

预训练让模型获得了通用的语言能力，但**如何把这些能力用于不同任务**？

> **BERT / T5 的局限**
> BERT 的编码器不直接进行自回归生成。T5 用 Text-to-Text 统一了任务形式，但学会新任务通常仍需训练数据适配——**格式统一不等于无需适配**。

GPT 把任务描述、示例和输入写进同一序列，让模型通过续写作答，带来两点变化：

**切换成本大幅降低**
遇到新任务，可以先调整输入的上下文，测试同一模型能否完成。

**更会利用上下文**
规模扩大后，模型在更多任务中能利用描述与少量示例识别要求。

## ③ 结构简单统一，便于扩展

当模型和数据规模不断扩大，**能否高效训练和部署**就成为影响技术路线的关键。

> **BERT / T5 的局限**
> BERT 的双向注意力适合语言理解，用于开放式生成需额外设计生成机制。T5 同时使用编码器、解码器和交叉注意力，**结构与工程链路更复杂**。

Decoder-only 用同一套网络、同一套参数，既处理已有上下文又生成后续内容，带来工程红利：

*   **训练更易扩展**
    重复堆叠的解码器层便于划分计算与存储，组织大规模分布式训练。

*   **推理优化清晰**
    围绕逐个 Token 生成，可用 KV Cache、批处理、推理调度降开销、提吞吐。

*   **经验可复用**
    显存管理、量化、计算内核等优化，可迁移到结构相近的模型上。

## 训练、任务与结构的三方协同

训练目标简单，才能充分利用海量数据；任务表达统一，才能广泛承载不同应用；模型结构规整，才能持续扩大规模。三方面相互促进，共同推动 Decoder-only 成为主流。
