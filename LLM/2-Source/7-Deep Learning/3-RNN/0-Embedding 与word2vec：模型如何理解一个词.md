# Embedding 与word2vec：模型如何理解一个词

## 词必须先变成可计算的表示

人看到“苹果”，会自然联想到水果、味道、颜色和生活场景。

但计算机看到的只是一个离散符号 $\rightarrow$ 不能直接做加法，也不能判断“苹果和香蕉”是否比“苹果和汽车”更接近。
![](../../../../image/Pasted%20image%2020261026163727.png)
> [!important] 核心问题
> 所以，NLP 的第一个基础问题是：**如何把一个词变成可以处理、可以比较、可以学习的数字表示？**

## 最直接的办法：给每个词一个整数编号

既然计算机只能处理数字，一个最自然的方案就是编号：
`苹果 = 1` `香蕉 = 2` `汽车 = 3` `火车 = 4`
![](../../../../image/Pasted%20image%2020261026164024.png)

> [!info] 两种不同的使用场景
> 
> **1. 只用来查表时**
> 编号只是地址：第 1 个位置取出苹果，第 2 个位置取出香蕉。
> 
> **2. 直接交给模型计算时**
> 编号就变成普通数字。

> [!warning] 核心缺陷
> 任意的词表排列会被误读成**大小和距离**，而这些关系没有语义依据。
> *(例如：如果模型直接计算，可能会误认为 `汽车(3) - 香蕉(2) = 苹果(1)`，或者认为 `火车(4) > 苹果(1)`，这在语义上是荒谬的)*

## 能不能只表示身份，不制造大小和距离？

整数编号的问题，不是数字选得不好，而是**一个数值同时带来了身份、大小和距离**。

> [!info] 解决思路
> 不要再把词挤进一条数轴，而是给每个词一个**互不重叠**的位置。


![](../../../../image/Pasted%20image%2020261026164236.png)

```text
苹果 = [1, 0, 0, 0]
香蕉 = [0, 1, 0, 0]
汽车 = [0, 0, 1, 0]
火车 = [0, 0, 0, 1]
```
>[!important] 核心结论  
**独热编码 (One-Hot Encoding)** 用 0 和 1 只回答“这是哪个词”，不再暗示谁大、谁小。
## One-Hot 避开了假顺序，却带来稀疏高维
![](../../../../image/Pasted%20image%2020261026164416.png)

> [!warning] 维度随词表增长
> 10 万词就对应 10 万维向量。

> [!warning] 几乎全是 0
> 每个词只有自己的位置是 1。

> [!warning] 计算仍然昂贵
> 身份编码变清楚了，语义关系还没有出现。

## One-Hot 中，所有词都正交

图中夹角为 $90^\circ$ 时，余弦相似度为 0。One-Hot 的不同位置互相正交，任意两个不同词的相似度都是 0。
![](../../../../image/Pasted%20image%2020261026164545.png)
### 余弦相似度与向量关系

余弦相似度公式：
$$
\cos(\theta) = \frac{x \cdot y}{\|x\| \|y\|}
$$
### One-Hot 向量计算示例

由于不同词的 One-Hot 向量在完全不同的维度上取值为 1，它们的点积必然为 0（即互相正交）：

$$
[1, 0, 0, 0] \cdot [0, 1, 0, 0] = 0
$$

$$
[1, 0, 0, 0] \cdot [0, 0, 1, 0] = 0
$$

> [!important] 核心结论
> 苹果与香蕉、苹果与汽车，在模型眼里**没有区别**。One-Hot 消除了假顺序，却没有表达谁在语义上更接近谁。

## 语义来自上下文，而不是单个位置
如果要知道苹果为什么比香蕉更接近汽车，就必须观察它们在语言中如何被使用。
```text
上下文（语境中的词语使用） ──> 分布式假设 ──> 向量空间（语义空间）
> [!example] 上下文相似的例子  
> **句子组 1：**
> - 我吃了一个**苹果**。
> - **苹果**很甜。
> **句子组 2：**
> - 我吃了一个**香蕉**。
> - **香蕉**很甜。
> **对比组：**
> - 这辆**汽车**非常漂亮，轮毂很亮。
**推导过程：**
```

![](../../../../image/Pasted%20image%2020261026164947.png)
> [!info] 为什么不需要字面包含？  
> 苹果和香蕉并没有把“水果”“味道”“颜色”写在字面上，但它们经常出现在相似的位置：都可以被吃，都可以是甜的，也常和水果、价格、颜色一起出现。
  
这就是分布式假设：一个词的含义，可以通过它经常出现的上下文来理解，意思相近的词上下文也相似。
因此我们需要把**上下文中的相似性**转化成**向量空间中的接近关系**。
## 共现矩阵记录上下文关系，但还不等于语义空间

> [!info] 什么是共现矩阵？
> 共现矩阵（co-occurrence matrix）是统计学里的经典做法：统计一个词和哪些上下文词经常出现在同一个窗口里。
> **每行是一个词，每列是一个上下文词，格子里是它们共同出现的频率。**

### 共现矩阵示例

| | 吃 | 甜 | 水果 | 道路 | 发动机 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **苹果** | 38 | 24 | 31 | 1 | 0 |
| **香蕉** | 35 | 28 | 29 | 0 | 0 |
| **汽车** | 0 | 0 | 1 | 27 | 33 |
| **火车** | 0 | 0 | 0 | 21 | 18 |

> [!success] 优点：已经带上了 One-Hot 缺失的语义
> - **苹果**和**香蕉**的行向量会比较相似，**汽车**和**火车**也是。
> - 词不再只是孤立位置，而是由它和上下文词之间的关系来描述。

> [!failure] 缺点：记录了关系，却还没学出稳定的语义空间
> - **规模太大**：词表越大矩阵越大，100 万词就是 100 万 $\times$ 100 万，存储和计算都很重。
> - **泛化有限**：低频词行向量不稳定，没进词表的词没有位置，证据不足时相似性也难表示。
> - **统计太零散**：共现次数不会自动把稀疏、带噪声的统计压缩成紧凑的语义空间。

## 还差最后一步：把关系压缩成坐标

问题已经不是“词能不能变成数字”，而是“数字能不能保留语义关系，又适合模型学习”。

| 尝试阶段      | 方法          | 局限与问题                 |
| :-------- | :---------- | :-------------------- |
| **尝试 01** | **整数编号**    | 变成了数字，却带来虚假的大小和距离。    |
| **尝试 02** | **One-Hot** | 消除假顺序，却让所有词互相正交，没有语义。 |
| **尝试 03** | **共现矩阵**    | 用上了上下文，却太高维、太稀疏、不稳定。  |


> [!important] 最终解：Embedding
> 保留“相似上下文 $\rightarrow$ 相似语义”的线索，同时压缩成**低维、密集、可学习的连续坐标**——这类方法，就叫 **Embedding**。

## Embedding 把离散词放进连续空间
**Embedding** 把原本离散、孤立的对象“嵌入”到一个连续向量空间里：词不再只是词表里的一个位置，而是有了可以计算的坐标——能参与距离、相似度、聚类和分类。
```text
相似度(苹果, 香蕉) > 相似度(苹果, 汽车)
苹果 = [0.31, -0.82, 0.56, 0.14, ...]
```

|位置是训练来的|看整条向量，不看单一维度|
|---|---|
|词向量中的每一个坐标值，都是模型在训练过程中不断更新得到的，而不是人工赋予的。|单个数字不必对应甜度或颜色，是整条向量合起来决定了词的位置。|

> [!important] 核心结论  
> 语义关系就藏在词与词的位置关系里——让它真正高效可训练的经典方案，就是 **Word2Vec**。

## Word2Vec 改变了学习词向量的方式

在 Word2Vec 之前，词向量已经存在，但存在一定的问题：

| BEFORE（换个目标 $\rightarrow$） | AFTER |
| :--- | :--- |
| **共现矩阵降维 (LSA)** 能提取低维结构，却绕不开规模、稀疏和噪声。<br><br>**神经语言模型 (NNLM)** 主目标是预测下一个词，学到的词向量只是个副作用，成本过高。 | Word2Vec 不构建完整语言模型，而是把**学习词向量本身**变成轻量预测任务。<br><br>反复根据上下文预测、用误差调整向量——**相似上下文的词逐渐靠近**。 |

> [!math] 经典向量类比
> $$
> \text{vec(King)} - \text{vec(Man)} + \text{vec(Woman)} \approx \text{vec(Queen)}
> $$
> 
> “国王”减掉“男人”、再加上“女人”，结果最接近“女王”——**词之间的关系变成了向量空间里可以加减的方向。**

> [!important] 核心结论
> 这说明向量空间不只记录统计相关性，还编码了部分**语义和语法结构**。实现它的两种经典训练方式，就是 **CBOW 与 Skip-Gram**。

## CBOW: 用上下文共同猜中心词

> [!example] 直观示例
> 原始句子：`我 今天 想 吃 苹果`
> 
> 设定**窗口大小 = 2**：
> - **中心词** = `想`
> - **上下文** = `我、今天、吃、苹果`
> - **输入**：我、今天、吃、苹果
> - **输出**：想

![](../../../../image/Pasted%20image%2020261026170840.png)
> [!info] 初始状态
> 训练开始时，每个词向量是随机的。CBOW 取出上下文词向量求平均，得到一个上下文表示，再用它预测中心词。

> [!important] 核心总结与特点
> **完整流程**：滑动窗口取上下文 $\rightarrow$ 合并上下文向量 $\rightarrow$ 预测中心词 $\rightarrow$ 预测错了就反向传播，更新词向量和输出层。
> 
> **特点**：因为多个上下文词共同“投票”来预测中心词，CBOW **训练较快，也比较平滑**。

## Skip-Gram: 用中心词分别预测周围词
> [!example] 直观示例
> 原始句子：`我 今天 想 吃 苹果`
> 
> 设定**窗口大小 = 2**，**中心词 = 想**：
> - 输入：想
> - 输出：我、今天、吃、苹果
> *(相当于把一条语料拆成了 4 条独立的训练样本)*


![](../../../../image/Pasted%20image%2020261026171008.png)
### 核心机制
Skip-Gram 先取出中心词向量，再用它**分别预测**窗口里的每个上下文词。
如果真实上下文是“吃”，模型却更相信“汽车”，误差就会**反向更新中心词向量**。
## CBOW 和 Skip-Gram 方向相反，偏向不同
![](../../../../image/Pasted%20image%2020261026171136.png)

> [!info] 核心对比
> 
> | 对比维度 | CBOW (Continuous Bag of Words) | Skip-Gram (Continuous Skip-Gram) |
> | :--- | :--- | :--- |
> | **预测方向** | 用**上下文**猜**中心词** | 用**中心词**猜**上下文** |
> | **输入/输出** | 输入：上下文<br>输出：中心词 | 输入：中心词<br>输出：上下文 |
> | **偏向与特点** | 求平均、训练更快，**偏向高频词**。 | 拆出多样本，**偏向低频词与专有名词**。 |
> | **图示机制** | `[吃, 了, 一个]` $\rightarrow$ 平均/求和 $\rightarrow$ `苹果 / 香蕉` | `苹果` $\rightarrow$ 词向量表示 $\rightarrow$ `[我, 吃, 了, 一个]` |
> | **适用场景** | 计算高效，适合常见词。 | 适合学习低频词和小数据集。 |

> [!important] 核心结论
> 无论方向如何，Word2Vec 的真正意义都是：**通过预测上下文，让语义关系自动进入向量空间。**

## 用 gensim 训练《西游记》：从文本到词向量

### 完整训练流程

| 步骤 | 操作 |
| :--- | :--- |
| **① 读取 & 切句** | 按中文标点把全文粗切成句子 |
| **② jieba 分词** | 每句切成词，得到词序列列表 |
| **③ Word2Vec 训练** | 词序列列表就是训练输入 |

### Python 代码实现

```python
import re
import jieba
from gensim.models import Word2Vec

# 1. 读取文本
text = open("data/西游记.txt", encoding="utf-8").read()

# 2. 先按中文标点粗略切成句子
sentences = re.split(r"[。！？；!?;]", text)

# 3. 再用 jieba 把每个句子切成词，过滤掉纯空白字符
tokenized_sentences = [
    [w for w in jieba.cut(s) if w.strip()]
    for s in sentences if s.strip()
]

# 4. 训练 Word2Vec 模型
model = Word2Vec(
    sentences=tokenized_sentences,
    vector_size=100,    # 词向量维度
    window=5,           # 上下文窗口，左右各 5 词
    min_count=3,        # 过滤词频低于 3 的低频词
    sg=1,               # 1=Skip-Gram, 0=CBOW
    epochs=1000,
    workers=4,
)

# 5. 查找与“孙悟空”最相似的 10 个词
model.wv.most_similar("孙悟空", topn=10)
```
>[!info] 核心参数说明
>- `vector_size=100`：最终每个词会变成一个 100 维的稠密向量。
>- `window=5`：模型在预测时，会看中心词左右各 5 个词作为上下文。
>- `min_count=3`：出现次数少于 3 次的生僻词会被丢弃，减少噪声。
>- `sg=1`：**切换 CBOW 与 Skip-Gram 只需要改 `sg` 一个参数**（1 为 Skip-Gram，0 为 CBOW）。

## 验证一：相似的词，向量真的更接近吗
训练后每个词都有了向量。用**余弦相似度**就能检验：语义相近的词，是否在空间里也更接近。
### 代码实现
```python
import numpy as np
def cosine_similarity(x, y):
    return np.dot(x, y) / (
        np.linalg.norm(x) * np.linalg.norm(y))
# 手动计算，或直接用 gensim 封装
model.wv.similarity("孙悟空", "唐僧")
model.wv.similarity("孙悟空", "唐太宗")
# 查看最接近孙悟空的词
model.wv.most_similar("孙悟空", topn=10)

```
### 对比结果

|对比组合|余弦相似度|
|---|---|
|孙悟空 vs 唐僧|**0.17**|
|孙悟空 vs 唐太宗|0.05|

### 与「孙悟空」最相近的词（Top 4）

|词|相似度|
|---|---|
|齐天大圣|0.53|
|沙悟净|0.52|
|猪悟能|0.48|
|阿罗汉|0.44|

> [!important] 核心结论  
> 不是模型读懂了剧情，而是这些词在语料中的**上下文差异**，被训练反映进了向量空间。

## 验证二: 把高维词向量投影到平面上
### 降维可视化：用 PCA 观察词的相对位置
训练出的词向量有 100 维，无法直接画出。用**主成分分析 (PCA)** 压到二维，就能观察多个词的相对位置。
### PCA 降维代码
```python
from sklearn.decomposition import PCA
import numpy as np
# L2 归一化，让 PCA 关注方向而非长度
X = X_raw / (np.linalg.norm(
    X_raw, axis=1, keepdims=True) + 1e-12)
pca = PCA(n_components=2)
points = pca.fit_transform(X)

```
>[!important] 可视化结论  
取经团队、神佛、妖怪、地点物品各自聚成一团——  
**相似上下文 →→ 相似向量 →→ 局部聚集。**

## Embedding 是现代 AI 的通用接口
神经网络擅长处理连续张量，却不能直接处理离散符号。**Embedding 就是通用接口**：为每个离散对象学一个向量表示，再送进后续模型。
```text
离散对象 (词 / 用户 / 图片 / 序列) ──> Embedding (查表 / 编码) ──> 连续向量 ──> 进入后续模型

```
### 跨领域的通用应用

| 领域模型            | 应用机制                      |
| --------------- | ------------------------- |
| **Transformer** | `token` 先映射成向量，再进入自注意力层。  |
| **RAG**         | 文档片段和问题都编码成向量，再做相似度搜索。    |
| **推荐系统**        | 用户和商品都表示成向量，接近意味着潜在兴趣。    |
| **图像模型**        | 图片 `patch` 可以映射成向量，再进入模型。 |
| **蛋白质模型**       | 氨基酸序列也可以映射到连续空间。          |

> [!important] 核心结论  
> 只要对象原本是**离散的、符号化的、不能直接交给神经网络处理**的，就可以先把它映射到同一种**可计算的连续空间**。

## 词已经进入空间，但句子理解才刚开始

| Embedding 完成的事 | Embedding 还不够的地方 |
| :--- | :--- |
| 文字不再只是离散符号，而是进入了可以计算相似度、参与矩阵运算、被模型继续更新的连续空间。 | `我不喜欢这部电影` 和 `我喜欢这部电影` 只差一个 `不`，语义却完全相反；<br><br>`苹果发布了新产品` 和 `我吃了一个苹果` 中的苹果，含义也不相同。 |

> [!important] 核心结论
> 真正的语言理解，还要继续处理**词与词之间的关系**。
