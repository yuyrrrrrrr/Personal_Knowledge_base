# Linux 运维学习总结

## 1-System Management

- Linux 发行版由内核、系统工具和软件包体系组成，系统管理需要理解用户、权限、进程、服务和文件系统。
- 用户与组管理遵循最小权限原则，核心命令包括 `useradd`、`usermod`、`groupadd`、`passwd`、`id`。
- 权限管理通过 `chmod`、`chown`、`chgrp`、`umask` 和 ACL 控制属主、属组及其他用户的访问。
- `ps`、`top`、`kill`、`nice`、`systemctl` 分别用于查看、控制进程和管理系统服务。
- 磁盘管理涉及分区、文件系统、挂载、`/etc/fstab`、`df`、`du` 和 LVM；软件包通过 `apt` 或 `dnf`/`yum` 管理。

## 2-Shell Scripting

- Shell 脚本通过 Shebang、变量、命令替换、退出码和严格模式提高自动化可靠性。
- 变量展开应使用引号，数组通过 `${array[@]}` 遍历并保留元素边界。
- `if`、`case`、`for`、`while` 用于实现条件分支和循环流程。
- 函数使用 `local` 控制作用域，位置参数、`$#`、`$@` 和 `$?` 用于传递和处理结果。
- 管道、重定向、文本处理命令和 Cron 常用于日志分析、系统巡检、备份和定时自动化。

## 3-Administration of Networks

- 网络管理需要理解 IP、子网掩码、网关、MAC、端口、TCP/UDP 和 DNS。
- `ip addr`、`ip link`、`ip route`、`nmcli` 和发行版网络配置工具用于管理网络接口和地址。
- DNS、网关和路由错误会导致访问失败，应分别检查 `/etc/hosts`、`resolv.conf` 和路由表。
- `ping`、`traceroute`、`mtr`、`ss`、`curl`、`dig`、`nc` 用于分层验证网络连通性和服务状态。
- `tcpdump`、Wireshark、`iftop`、`nethogs` 和防火墙工具用于抓包、流量分析和访问控制。

## 4-System Monitoring

- 监控覆盖可用性、性能、容量、错误率和业务状态，并需要建立基线和告警策略。
- CPU 监控关注用户态、内核态、I/O 等待、负载和进程级热点。
- 内存监控要区分可用内存、缓存、常驻内存、交换和 OOM。
- 磁盘监控关注容量、inode、I/O 利用率、响应时间和进程级读写。
- 网络监控关注带宽、连接数、丢包、延迟和重传；Prometheus、Grafana、Zabbix 和告警流程用于平台化管理。

## 5-Log Analysis And Fault Troubleshooting

- 日志覆盖系统、服务、安全和应用行为，常用目录为 `/var/log`，`dmesg` 和 `journalctl` 用于内核及 systemd 日志。
- `logrotate` 控制日志轮转、压缩和保留周期，避免日志持续占满磁盘。
- `grep`、`sed`、`awk` 分别用于搜索、流式编辑和按列统计，是多机日志分析的基础。
- 故障排查应按网络、主机资源、进程、配置、依赖和业务逻辑分层进行，并保留现场证据。
- 应急流程强调先止损、再定位、后修复，最后通过复盘更新监控、预案和自动化检查。

## 6-Security Reinforce

- 安全加固遵循最小权限、默认拒绝、纵深防御和最小暴露原则。
- SSH 应优先使用密钥认证，限制登录用户和来源，并谨慎修改远程访问配置。
- 用户、组、`sudo`、密码策略和文件权限需要定期审计，避免异常提权入口。
- 防火墙要同时检查主机规则、云安全组和网络 ACL，只开放必要端口。
- 入侵检测、审计日志、补丁管理、加密备份和恢复验证共同构成持续安全维护。

## 7-Automated Operations Management

- 自动化运维要求流程幂等、可观测、可回滚，并减少重复劳动和人为错误。
- Ansible 通过 Inventory、模块和 Playbook 实现无代理配置管理。
- 配置与代码应版本化，Playbook 优先使用幂等模块并经过测试和差异检查。
- Docker 提供镜像、容器和持久化能力，Kubernetes 提供调度、服务发现、副本管理和自愈。
- CI/CD 把代码、测试、构建、扫描、部署和验证串成流水线，安全凭据和最小权限贯穿全过程。
