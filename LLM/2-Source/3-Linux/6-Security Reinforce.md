## 1. 安全加固基础

- 安全加固的目标是降低攻击面、限制权限、提高可检测性和可恢复性。
- 遵循最小权限、默认拒绝、纵深防御和最小暴露原则。
- 定期盘点系统资产、开放端口、运行服务、账号和定时任务。
- 配置和密钥应集中管理，禁止把敏感信息写死在脚本或仓库中。
- 安全措施必须结合业务可用性，不能只追求表面上的限制。
- 任何加固操作都要有测试、备份、变更记录和回滚方案。

## 2. SSH 安全配置

```bash
sudo sshd -t
sudo systemctl reload sshd
```

- 禁止直接使用 `root` 远程登录，日常管理使用普通用户加 `sudo`。
- 优先使用密钥认证，关闭密码登录或限制密码登录来源。
- 修改默认端口只能减少扫描噪声，不能替代认证和防火墙控制。
- 限制 `AllowUsers`、`AllowGroups` 或来源地址，减少可登录范围。
- 关闭不必要的转发、隧道和代理功能。
- 修改 `sshd_config` 后先执行语法检查，并保留现有会话验证，避免把自己锁在服务器外。

## 3. 用户权限与 sudo

```bash
visudo
sudo -l -U alice
```

- 删除或锁定不必要的默认账号和测试账号。
- 使用用户组管理权限，避免为每个用户重复分配规则。
- `sudo` 授权应限定命令、参数和主机范围。
- 只读运维可以使用只读命令集合，避免授予完整 root 权限。
- 定期审计 `sudoers`、登录用户、SSH 公钥和文件权限。
- `SUID`/`SGID` 文件应定期盘点，发现异常提权入口立即处理。

## 4. 密码与认证策略

- 设置密码复杂度、最小长度、有效期和历史密码限制。
- 对连续登录失败进行锁定或延迟，但必须避免影响正常服务账号。
- 高权限操作建议启用多因素认证。
- 服务账号优先使用密钥、证书或短期凭据，不使用弱密码和共享密码。
- 密码哈希和密钥文件必须限制读取权限。
- 认证策略应结合 PAM、SSH、应用账号和集中身份系统统一管理。

## 5. 防火墙与端口管理

```bash
ss -tulnp
firewall-cmd --list-all
```

- 先确认真正需要对外提供的服务，再关闭其他监听端口。
- 同时检查 systemd 服务、`iptables`/`nftables`、`firewalld`、云安全组和网络 ACL。
- 规则应限制来源地址、协议、端口和访问方向。
- 临时调试规则必须设置到期时间或及时清理。
- 修改远程防火墙前保留可回滚通道，避免失去 SSH 访问。
- 对数据库、缓存、管理后台等内部服务禁止直接暴露公网。

## 6. 入侵检测与安全审计

- 检查异常登录时间、来源 IP、失败次数和新出现的 SSH 密钥。
- 使用 `last`、`lastb`、`who`、`journalctl` 和认证日志分析登录行为。
- 文件完整性工具可以监控关键二进制、配置和系统文件的变更。
- `auditd` 可以记录系统调用、文件访问和权限相关事件。
- `SELinux`、`AppArmor` 可以提供强制访问控制，但需要理解策略模式和日志。
- 发现入侵迹象后先隔离、保留证据和评估影响，不要直接覆盖现场。

## 7. 补丁、备份与安全维护

- 建立补丁评估、测试、灰度、部署和回滚流程。
- 关注内核、OpenSSL、SSH、Web 服务、数据库和容器运行时的高危漏洞。
- 安全更新不能盲目在生产环境一次性全量执行。
- 备份应加密、隔离并定期验证恢复，不能只验证备份脚本成功。
- 定期执行端口扫描、账号审计、权限审计和日志检查。
- 安全是持续过程，应将检查项纳入自动化巡检和告警。
