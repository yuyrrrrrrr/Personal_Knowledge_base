# 流式输出的基本原理
在普通 HTTP 请求中，客户端发送请求后，服务端需要完成整个任务并生成完整响应，随后一次性返回给客户端。客户端通常需要等待完整响应体接收完成后，才能解析数据并更新界面。

而在流式 HTTP 请求中，服务端不需要等待所有内容生成完毕，而是可以在生成过程中分批发送数据。客户端每收到一段数据，就可以立即进行解析和渲染，实现边接收、边处理、边展示。对于大模型应用来说，这意味着用户不必等待模型生成完整答案，就能看到第一个 Token，后续内容也会持续输出，从而显著改善交互的实时性和等待体验。

为了把这段连续的数据让客户端消费，大模型 API 通常使用**服务端发送事件（Server-Sent Events，SSE）**格式。服务端通过 HTTP Header 返回 `Content-Type: text/event-stream`，保持 HTTP 连接，再不断写入事件。

使用 FastAPI 写一个最简单的服务器流式输出 demo：
```python
import json
import asyncio
from contextlib import aclosing
from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()


# 模拟模型生成事件，每隔一秒返回一段文本
async def generate_events():
    # 告诉客户端响应开始
    yield {"type": "run.started"}

    # 模拟逐步生成内容
    for text in ["Agent", "开发", "很简单！"]:
        await asyncio.sleep(1)
        yield {
            "type": "message.delta",
            "content": text
        }

    # 告诉客户端响应结束
    yield {"type": "run.completed"}


# 将业务事件编码为 SSE 格式
async def encode_sse(events):
    # 客户端断开连接时，关闭异步生成器
    async with aclosing(events):
        async for event in events:
            # 将字典转换为 JSON 字符串，保留中文
            data = json.dumps(event, ensure_ascii=False, separators=(",", ":"))

            # SSE 使用 data 字段传输数据，两个换行符表示一条事件结束
            yield f"data: {data}\n\n"


@app.post("/api/chat")
async def chat():
    # 返回 HTTP 流式响应
    return StreamingResponse(
        encode_sse(generate_events()),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache"},
    )
```
每个 `data:` 块后面用空行标记一个事件的结束，JSON 内的字段由应用自行约定。这个 Server 使用业务事件传输模型输出，下面是一个简化的示意：
```
data: {"type":"run.started"}

data: {"type":"message.delta","content":"Agent"}

data: {"type":"message.delta","content":"开发"}

data: {"type":"message.delta","content":"很简单！"}

data: {"type":"run.completed"}
```
每条 SSE 消息使用空行标记本事件的结束，客户端需要先把收到的字节解码成文本，再按照 SSE 边界还原完整事件，最后按应用协议读取其中的数据。
# 客户端如何接收流式数据？
浏览器原生提供了 `EventSource` API，可以直接接收 SSE 事件，但它只支持 GET 请求，不能提交 POST 请求体，也没有设置任意自定义请求头的接口。

大模型 API 通常需要通过 POST 提交模型参数和对话历史，如果应用希望在同一次请求里提交输入并接收流式结果，就可以使用 Fetch API 发起 POST，再通过 ReadableStream 读取响应体。
```python
const response = await fetch("/api/chat", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    "Accept": "text/event-stream",
  },
  body: JSON.stringify({
    prompt: "介绍一下 Agent 开发",
  }),
});

// 获取响应体的 ReadableStream
const reader = response.body.getReader();

// 创建解码器，将 Uint8Array 转换成字符串
const decoder = new TextDecoder();

const chunkLog = document.querySelector("#chunk-log");

while (true) {
  // 持续读取服务端返回的数据
  const { value, done } = await reader.read();

  // 数据读取完毕，退出循环
  if (done) break;

  // 将字节数据解码为文本
  const chunk = decoder.decode(value, {
    stream: true,
  });

  // 实时更新页面
  chunkLog.textContent += chunk;
}

// 刷新解码器中可能残留的字节
chunkLog.textContent += decoder.decode();
```
通过 `getReader()` 获取读取器后，应用不断调用 `read()`，直到 `done` 表示响应体已经结束。
如果不想自己处理 SSE 解析，可以直接使用微软开源的 `@microsoft/fetch-event-source`。

下面通过 `onmessage` 获取已经解析好的 SSE 事件，这个 demo 假设非空的事件数据都是 JSON，如果后端还发送 `[DONE]`，则需要在 JSON 解析前单独处理：
```python
import { fetchEventSource } from "@microsoft/fetch-event-source";

// 创建 AbortController，用于在需要时主动中断请求
const controller = new AbortController();

// 获取页面中用于展示模型回答的 DOM 元素
const answerElement = document.querySelector("#answer");

await fetchEventSource("/api/chat", {
  method: "POST",

  // 设置请求头，声明请求体为 JSON 格式
  headers: {
    "Content-Type": "application/json",
  },

  // 发送给服务端的请求参数
  body: JSON.stringify({
    prompt: "介绍一下 Agent 开发",
  }),

  // 将 AbortController 的 signal 传入请求，后续可以通过 controller.abort() 中断连接
  signal: controller.signal,

  // 接收到服务端推送的 SSE 事件时触发
  onmessage(event) {
    // 忽略没有数据的事件
    if (!event.data) return;

    // SSE 的 data 字段是字符串，这里将其解析为 JSON 对象
    const data = JSON.parse(event.data);

    // 只处理模型生成的增量文本事件
    if (data.type === "message.delta") {
      // 将本次收到的文本追加到页面，实现逐字流式输出
      answerElement.textContent += data.content;
    }
  },

  // 请求发生错误时触发
  onerror(error) {
    // 抛出异常，终止自动重试，并将错误交给调用方处理
    throw error;
  },
});
```
这个库保留了 Fetch API 的请求能力，支持 POST、请求头、请求体和 AbortController，同时封装了 SSE 解析，出错后是否重试由 `onerror` 决定。

到这里，客户端已经能够收到完整事件，但事件里应该包含什么，还取决于应用要向用户展示哪些执行状态。
# Agent 事件协议
通过 SSE 传给客户端的数据，可以包含回答文本、工具执行状态、任务进度等内容。客户端需要识别这些数据的含义，才能将它们展示在界面的相应位置。

如果界面只需要逐字显示回答，客户端可以直接拼接收到的文本。但在 Agent 应用中，我们还希望展示“正在搜索资料”“工具执行完成”等状态，或者根据返回的数据更新进度、展示结果卡片。这就需要客户端能够区分当前收到的是一段回答、一次状态变化，还是一份结构化结果。

因此，服务端与客户端需要约定统一的事件类型和数据结构。例如，`message.delta` 表示文本增量，客户端将其追加到回答区域；`tool.started` 表示工具开始执行，客户端展示对应的执行状态；`run.completed` 表示整个任务完成，客户端结束加载状态。
![](Pasted%20image%2020261116092611.png)
有了明确的事件约定，客户端就能根据事件类型选择相应的渲染方式，将 Agent 的执行过程呈现为清晰、连贯的交互界面。下面是一组简单的业务事件示例：

| **事件**         | **含义**   | **前端展示**   |
| -------------- | -------- | ---------- |
| run.started    | 任务开始执行   | Agent 正在执行 |
| message.delta  | 文本增量     | 逐步展示回答     |
| tool.started   | 工具开始执行   | 正在搜索       |
| tool.completed | 工具执行完成   | 搜索完成       |
| agent.handoff  | Agent 交接 | 正在切换 Agent |
| task.progress  | 任务进度变化   | 已完成 2/5    |
| run.completed  | 任务执行完成   | 任务完成       |
| run.failed     | 任务执行失败   | 展示错误信息     |

Agent 后端根据实际执行状态生成事件，将其序列化为 JSON，通过 SSE 的 `data:` 字段发送给客户端。例如，一条文本增量事件：
```python
data: {"type":"message.delta","content":"你好"}
```
客户端解析其中的 JSON，根据 `type` 字段调用对应的渲染逻辑，更新回答内容、工具状态或任务进度。
# Web 渲染示例
有了统一的业务事件结构，Web 端就可以通过 SSE 接收事件，再根据事件类型更新 UI。工具状态来自工具事件，回答内容来自文本增量，界面不需要再从模型生成的自然语言里猜测任务执行到了哪一步。
![](Pasted%20image%2020261116092719.png)
```python
import { fetchEventSource } from "@microsoft/fetch-event-source";

const answerElement = document.querySelector("#answer");
const stepsElement = document.querySelector("#steps");
const stateElement = document.querySelector("#state");
stateElement.textContent = "等待首段文字";

await fetchEventSource("/api/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ prompt: "介绍一下 Agent 开发" }),
  openWhenHidden: true,

  onmessage(event) {
    if (!event.data) return;
    const data = JSON.parse(event.data);

    if (data.type === "message.delta") {
      answerElement.textContent += data.content;
      stateElement.textContent = "正在输出";
    } else if (data.type === "tool.started") {
      stepsElement.textContent += `正在执行：${data.toolName}\n`;
    } else if (data.type === "tool.completed") {
      stepsElement.textContent += `执行完成：${data.toolName}\n`;
    } else if (data.type === "run.completed") {
      stateElement.textContent = "任务完成";
    } else if (data.type === "run.failed") {
      stateElement.textContent = `执行失败：${data.error}`;
    }
  },

  onclose() {
    if (stateElement.textContent === "正在输出") {
      stateElement.textContent = "连接提前结束";
    }
  },

  onerror(error) {
    throw error;
  },
});
```
收到 `message.delta` 时，前端将增量文本追加到当前回答；收到工具事件时，更新执行记录；收到任务终态事件时，结束等待。

除了文本和执行状态，事件流中还可以包含 UI 描述。例如，Agent 需要追问用户时，可以返回一个问题和三个选项。我们先用一个简单的自定义格式表示：
```python
{
  "type": "ui.question",
  "question": "你希望使用哪种语言开发 Agent？",
  "options": ["Python", "JavaScript", "Java"],
  "multiple": false
}
```
客户端收到这类事件后，将问题和选项渲染成一组单选按钮，用户选择后再把答案回传给 Agent。
![](Pasted%20image%2020261116092758.png)
我们也可以把对 UI 的描述规范化，统一约定组件、布局和交互的表达方式。[**A2UI**](https://a2ui.org/)**（Agent to User Interface）协议**就是为此设计的，Agent 按协议输出结构化的界面描述，客户端据此渲染和更新界面。
# 命令行工具渲染示例
命令行程序也可以作为流式接口的客户端，程序持续读取模型返回的数据，再把新内容写入标准输出，终端就会逐步显示回答。网络请求和事件解析由程序或 SDK 完成，终端负责显示程序输出的字符。

以 Python 调用 OpenAI SDK 为例，开启 `stream=True` 后，可以通过循环逐个读取返回的事件。收到文本增量时，将它直接输出：
```python
from openai import OpenAI

client = OpenAI()

stream = client.responses.create(
    model="你的模型名称",
    input="介绍一下 Agent 开发",
    stream=True,
)

for event in stream:
    if event.type == "response.output_text.delta":
        print(event.delta, end="", flush=True)

print()  # 文本输出结束后补一个换行
```
SDK 已经处理了底层的 SSE 解析，循环中的每个 `event` 都是解析后的事件对象。`event.delta` 是当前事件携带的新增文本，程序每收到一段就输出一段，无需等待完整回答。

设置 `end=""` 后多次收到的文本就能连续显示，`flush=True` 则用于及时刷新输出缓冲区，避免程序已经收到数据，终端却迟迟没有变化。

当 Agent 还需要调用工具时，命令行也可以消费前面约定的业务事件。每收到一条事件，就交给下面的 `render()` 函数处理：
```python
import sys

def render(event):
    kind = event["type"]

    if kind == "message.delta":
        print(event["content"], end="", flush=True)

    elif kind == "tool.started":
        print(f"\n[开始执行] {event['toolName']}",
              file=sys.stderr, flush=True)

    elif kind == "tool.completed":
        print(f"[执行完成] {event['toolName']}",
              file=sys.stderr, flush=True)

    elif kind == "run.completed":
        print()

    elif kind == "run.failed":
        print(f"\n[任务失败] {event['error']}",
              file=sys.stderr, flush=True)
```
模型的文本增量被转换为 `message.delta` 后，调用这个函数就会继续追加回答；工具开始、完成时，传入对应事件就会显示执行记录。整个任务的完成或失败由 Agent 后端判断，再通过事件通知命令行。
# 总结
流式输出让服务端在同一次 HTTP 响应中持续发送已经生成的内容，客户端边接收边展示，用户无需等待完整回答。SSE 约定了流中事件的组织格式，客户端可以通过 EventSource、Fetch 或模型 SDK 持续读取和解析。

应用还需要约定事件的业务含义，让客户端能够区分文本增量、工具状态和任务进度，并采取相应的展示方式。返回的数据也可以包含问题、选项等 UI 描述，由客户端渲染成交互组件；A2UI 则进一步规范了这类界面的描述方式。

Web 端通过更新页面展示回答、执行状态和交互组件，命令行通过持续写入并及时刷新终端输出展示内容。同一套业务事件约定，可以用于不同客户端的解析与渲染。
