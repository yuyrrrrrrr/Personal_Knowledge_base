## 1. 慢查询分析与执行计划

```sql
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;
EXPLAIN SELECT * FROM orders WHERE user_id = 100;
```

- 慢查询日志记录执行时间超过阈值的 SQL。
- 分析慢查询时关注执行次数、平均耗时、扫描行数和返回行数。
- `EXPLAIN` 查看访问类型、索引选择、连接顺序和预估行数。
- `EXPLAIN ANALYZE` 可以观察实际执行信息和耗时。
- 常见优化方向包括增加或调整索引、重写 SQL、减少回表、优化表结构。
- 不应只根据单次偶发慢查询立即创建索引，应先统计频率和影响。

## 2. 数据备份与恢复

```bash
mysqldump -u root -p --single-transaction --routines --triggers db_name > db.sql
mysql -u root -p db_name < db.sql
```

- 备份目标是保证数据可恢复，而不只是生成备份文件。
- 全量备份适合建立恢复基线，增量备份通过 binlog 缩短恢复时间。
- 逻辑备份使用 `mysqldump`，物理备份可使用 Percona XtraBackup 等工具。
- 备份策略应包括频率、保留周期、异地存储、加密和访问权限。
- 恢复流程必须定期演练，验证备份文件、恢复时间和数据完整性。
- 恢复前应确认目标环境、覆盖范围和业务影响。

## 3. 主从复制

```text
主库 binlog -> 从库 relay log -> 从库重放
```

- 主库把数据变更写入 binary log。
- 从库 I/O 线程读取主库 binlog 并写入 relay log。
- 从库 SQL 线程重放 relay log，从而保持数据同步。
- 一主多从可以提高读扩展能力和容灾能力。
- 主从延迟可能来自网络、单线程回放、大事务和从库负载。
- 半同步复制可以降低数据丢失风险，但会增加提交延迟。
- GTID 复制简化故障切换和复制拓扑管理。

## 4. 读写分离

- 主库负责写操作，从库承担部分或全部读请求。
- 读写分离可以提升读吞吐并降低主库压力。
- 应用层读写分离实现简单，但需要管理数据源和路由逻辑。
- 中间件读写分离对应用透明，常见工具包括 MyCat 和 ShardingSphere。
- 由于复制延迟，刚写入的数据可能无法立即从从库读到。
- 强一致性读取应路由到主库，最终一致场景可使用从库。
- 故障切换时必须处理主从角色变化、连接重定向和事务状态。

## 5. 高可用架构

- 高可用目标是减少单点故障和缩短故障恢复时间。
- 常见方案包括主从、双主、MHA、Group Replication 和 InnoDB Cluster。
- `Keepalived` 可以配合虚拟 IP 实现入口故障转移。
- 故障转移需要判断主库真实状态，避免脑裂和双主写入。
- 自动切换必须配合应用重连、只读状态和节点重新加入流程。
- 高可用方案必须经过故障演练，不能只验证正常路径。

## 6. 分库分表

- 数据量大、并发高或单表维护困难时，可考虑分库分表。
- 垂直拆分按业务或字段拆分，水平拆分按数据行拆分。
- 常见路由策略包括范围、哈希、时间和一致性哈希。
- 分片会带来跨库 JOIN、分布式事务、全局 ID 和聚合统计问题。
- 中间件可使用 ShardingSphere、MyCat 等，也可以由应用层路由。
- 分片键选择决定数据分布和查询效率，修改分片策略成本很高。
- 分库分表应是权衡后的架构决策，不应作为小规模系统的默认方案。

## 7. 云数据库服务

- 云数据库通常提供高可用、自动备份、监控、弹性扩容和容灾能力。
- 主流服务包括阿里云 RDS、腾讯云 CDB、AWS RDS 等。
- 云数据库与自建数据库的选择取决于成本、可控性、合规和运维能力。
- 使用云数据库仍需理解连接数、规格、存储、备份和参数限制。
- 应配置安全组、白名单、SSL 和最小权限账号。
- 云上成本要结合实例规格、存储、备份、流量和跨区域复制评估。

## 8. 权限、安全与生产运维

- 应用账号只授予必要数据库和表权限，禁止直接使用 `root`。
- 权限应区分读、写、DDL、备份和管理操作。
- 账号来源应限制到明确主机范围，生产环境避免使用过于宽泛的 `%`。
- 敏感数据需要加密、脱敏和访问审计。
- 数据库连接信息不能硬编码在代码或公开仓库中。
- 变更操作应经过审核、备份、灰度、验证和回滚。

## 9. 监控与故障排查

- 核心指标包括 `QPS`、`TPS`、连接数、慢查询数、缓冲池命中率和锁等待。
- 监控磁盘空间、复制延迟、主从状态、错误日志和备份结果。
- 连接数耗尽时检查连接池、空闲连接、慢 SQL 和异常流量。
- 死锁时结合错误日志、`SHOW ENGINE INNODB STATUS` 和业务事务顺序排查。
- 复制中断时检查网络、账号、binlog、relay log 和错误日志。
- 先止损再定位，避免直接重启数据库造成数据或现场丢失。

## 10. 生产最佳实践

- 数据库参数、版本和配置纳入版本管理和变更记录。
- 建立容量基线、监控告警、备份恢复和故障演练机制。
- 大事务应拆分，热点行更新应控制并发。
- 在线 DDL、批量更新和索引变更要评估锁与主从影响。
- 定期检查慢查询、无用索引、碎片、账号权限和异常连接。
- 所有架构能力都要配套应急预案、回滚方案和责任人。
