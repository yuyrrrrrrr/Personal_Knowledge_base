# MySQL 学习总结

## 1-Database Theory and MySQL Basics

- 数据库用于持久化管理数据，关系模型由表、行、列、主键、外键、约束和视图等概念组成。
- 数据库设计需要理解一对一、一对多、多对多关系和三大范式，并在范式化与查询性能之间权衡。
- SQL 分为 `DDL`、`DML`、`DQL`、`DCL`、`TCL`，分别负责结构定义、数据操作、查询、权限和事务控制。
- MySQL 基础操作包括安装连接、数据库与数据表管理、数据类型、约束、存储引擎和 CRUD。
- 基础查询需要掌握 `SELECT`、`WHERE`、运算符、`LIKE`、`IN`、`BETWEEN`、`NULL`、排序、分页和去重。

## 2-SQL Practical Application and Advanced Topics

- 聚合函数、字符串函数、日期函数、数学函数、条件函数和类型转换函数是 SQL 数据处理的基础工具。
- `GROUP BY` 与 `HAVING` 用于分组统计，`WHERE` 在分组前过滤，`HAVING` 在分组后过滤。
- 多表查询包括内连接、外连接、自连接和交叉连接，需要明确连接条件和结果粒度。
- 子查询、`UNION` 和窗口函数适合处理复杂分析、数据合并、排名、累计和前后行比较。
- 数据与表操作包括批量插入、条件更新、删除、视图、索引和表结构迁移，复杂查询需结合 `EXPLAIN` 优化。

## 3-MySQL High Availability and Production Practices

- 慢查询分析通过慢查询日志和 `EXPLAIN` 定位瓶颈，并从索引、SQL、表结构和配置方向优化。
- 备份与恢复需要覆盖全量、增量、binlog、保留周期、异地存储和恢复演练。
- 主从复制以 binlog、relay log 和重放机制为基础，需要处理复制延迟和一致性。
- 读写分离、高可用架构、分库分表和云数据库用于扩展并发、容量和容灾能力。
- 生产运维需要关注权限安全、监控指标、故障排查、变更审核、回滚和应急演练。

## 4-The underlying principles and performance optimization of MySQL

- MySQL 架构可分为连接层、服务层、引擎层和存储层，SQL 会经过解析、优化、执行和结果返回阶段。
- InnoDB 支持事务、行锁、MVCC 和崩溃恢复；B+ 树索引适合磁盘查找、范围查询和排序。
- 索引优化需要理解聚簇索引、二级索引、回表、覆盖索引、最左匹配和索引失效场景。
- 事务围绕 `ACID` 展开，隔离级别会影响脏读、不可重复读和幻读，MVCC、undo log、redo log 与 binlog 共同保证一致性和恢复能力。
- 锁机制和死锁控制依赖行锁、间隙锁、临键锁和访问顺序；性能优化需要结合 SQL、表结构、配置、硬件和真实压测。
