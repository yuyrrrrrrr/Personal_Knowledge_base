## 0. 先记住这 6 句话

1. **ChatGPT 的本质不是数据库检索，而是“对话模板 → token 序列 → 逐 token 预测下一个 token”。**
2. **预训练**把互联网文本压缩进神经网络参数，得到“互联网文档模拟器”——base model。
3. **SFT** 用人类编写的对话示范，把 base model 塑造成“有帮助的助手人格”。
4. **RLVR** 在数学、代码、游戏等**可验证领域**中，让模型通过大量试错自己发现推理策略。
5. **RLHF** 在笑话、诗歌、摘要等**不可验证领域**中，用人类偏好训练奖励模型，再用 RL 优化；但奖励模型容易被“钻空子”。
6. **LLM 的能力和缺陷都来自同一件事：它是用有限计算逐 token 预测的统计系统。** 因此会幻觉、不会真正数数、拼写很差、能力参差不齐。

## 1. 全局地图：LLM 的三阶段训练管线

|阶段|训练数据|学习信号|产物|一句话理解|
|---|---|---|---|---|
|**预训练 Pre-training**|互联网文档，约 15T tokens|预测下一个 token|**Base model**|把互联网“有损压缩”进参数|
|**监督微调 SFT**|人类/合成对话|人类写的理想助手回复|**Assistant model**|模仿人类标注员的对话行为|
|**强化学习 RL**|可验证题目、代码、游戏等|自动判定答案是否正确|**Reasoning model**|通过试错发现“怎么想”|
|**RLHF**|开放任务的多个回答及人类排序|人类偏好 → 奖励模型|**Aligned assistant**|用人类偏好模拟器做微调|

> 讲座实际顺序是：预训练 → SFT → LLM 心理学 → RLVR → AlphaGo → RLHF。  
> 本笔记把 RLVR 与 RLHF 都归入“强化学习”阶段，便于建立完整框架。

### 贯穿全场的核心区分：可验证领域 vs. 不可验证领域

> **可验证领域**：答案可以被程序或规则自动判定对错，例如数学题、代码测试、围棋胜负、形式逻辑。  
> **不可验证领域**：没有唯一正确答案，或正确性依赖人类判断，例如写笑话、写诗、摘要、文风、建议、价值观。

这个区分解释了整场讲座最重要的现象：

- **在可验证领域**，RL 可以使用“答案检查器”作为奖励，模型可以大量试错，甚至发现人类从未使用过的解法。
- **在不可验证领域**，只能用人类偏好训练“奖励模型”作为代理；奖励模型是可被优化的神经网络，容易被 reward hacking，因此 RLHF 通常只能训练几百步就必须停下。
- **SFT 在两个领域都存在**，但作用不同：在可验证领域提供“专家解法”作为初始化；在不可验证领域提供“理想助手回复”来塑造人格、格式和风格。
- **RLVR 是当前 frontier 的核心**；从可验证领域学到的推理能力能否迁移到不可验证领域，仍是开放问题。

# 2. 预训练：把互联网压缩进参数

## 2.1 预训练数据：高质量、多样性、超大规模

### 是什么

预训练的第一步是收集并处理互联网文本，目标是获得**数量巨大、质量高、主题多样**的文档，让模型学习语言、事实、世界知识和统计规律。

### 为什么重要

模型的知识上限很大程度由预训练数据决定。数据质量、语言比例、重复率、隐私信息处理，都会影响最终模型的能力和偏见。

### Karpathy 的例子

- 以 Hugging Face 的 **FineWeb** 数据集为例：最终约 **44 TB** 磁盘空间，约 **15 万亿 tokens**。
- 数据主要来自 **Common Crawl**：自 2007 年开始爬取互联网，2024 年已索引约 **27 亿个网页**。
- 打开 FineWeb 可以看到最终文本样本，例如“2012 年龙卷风”的文章、关于“人体肾上腺只有两颗黄色 9V 电池大小”的医学文章。
- Karpathy 把前 200 个网页的文本拼接起来并不断缩小视图，展示“巨大文本织锦”：模型要从中学习模式。

### 关键点

- 互联网很大，但经过文本提取和过滤后，真正用于训练的文本并没有想象中那么夸张。
- 数据不是“越多越好”，而是要在**质量、多样性、语言覆盖、重复率**之间做设计取舍。
- 不同公司会选择不同的语言比例。例如 FineWeb 以英语为主；过滤掉西班牙语，模型以后西班牙语能力就会弱。

---

## 2.2 数据清洗流水线

|步骤|做什么|为什么重要|
|---|---|---|
|**Common Crawl**|从种子网页出发，沿链接爬取互联网|提供海量原始网页|
|**HTML 文本提取**|去掉 HTML、CSS、导航栏、广告等，只保留正文|模型需要的是自然语言，不是网页代码|
|**语言过滤**|用语言分类器判断网页语言；FineWeb 例子中只保留英语占比 >65% 的页面|决定模型的多语言能力|
|**质量过滤**|去除低质量、垃圾、重复、模板化内容|低质量数据会浪费算力并污染模型|
|**去重 Deduplication**|删除重复或近似重复文档|防止模型过度记忆和复读|
|**PII 去除**|去除地址、社会安全号码等个人身份信息|降低隐私和合规风险|
|**Tokenization**|把文本转换成 token 序列|神经网络只能处理离散符号序列|

### Karpathy 的例子

他展示了网页原始 HTML 中大量标签、列表、CSS 等内容，说明“网页源码”与“正文文本”差别很大；数据清洗就是把前者变成后者。

## 2.3 Tokenization：把文本切成 token

### 是什么

神经网络需要**一维、有限符号集**的输入。Tokenization 就是把文本转换成 token ID 序列的过程。常用算法是 **BPE（Byte Pair Encoding）**：

1. 从字节开始；
2. 统计频繁出现的相邻符号对；
3. 把高频组合合并成新 token；
4. 重复多次，得到约 10 万规模的词表。

### 为什么重要

- Token 是模型真正“看到”的单位，不是字符，也不完全等于单词。
- 词表大小与序列长度之间需要权衡：词表越大，序列越短，但输出层和嵌入层越大。
- Tokenization 直接导致了模型在拼写、字符操作、计数等任务上的弱点。

### Karpathy 的例子

- GPT-4 使用的 tokenizer 约有 **100,277 个 token**。
- `hello world` 是两个 token：`hello` 和 `world`。
- `Hello World` 的大小写不同，tokenization 也不同。
- `hello world`（两个空格）又会产生不同 token。
- 一段普通文本可能被切成 62 个 token。
- 他用 **Tiktokenizer** 网站现场展示文本与 token 的对应关系。

### 核心结论

Token 是“文本块”，不是“字符”。模型看到的是 token ID，因此它天然不擅长逐字符任务。

---

## 2.4 神经网络的输入与输出

### 是什么

给定一个 token 序列作为输入，神经网络输出**词表中每个 token 作为下一个 token 的概率**。

### 为什么重要

这就是语言模型的训练目标：**Next-token prediction**。所有知识、语法、推理能力，都是在这个目标下被间接学到的。

### Karpathy 的例子

- 输入一个长度为 4 的 token 窗口，模型输出 100,277 个概率。
- 训练时我们知道真实的下一个 token，于是调整参数，让正确 token 的概率略微升高、其他 token 的概率降低。
- 实际训练会同时从数据中采样大量窗口和批次，对每个位置都做这种更新。
- 上下文窗口可以短到 0 个 token，也可以长到几千个 token；例子中常设为 8,000 左右。

### 关键点

- 模型不是“查表”，而是学习 token 之间的统计关系。
- 训练损失（loss）是一个数字，越低表示预测越准确。
- 训练过程是不断微调数十亿甚至数千亿个参数。

## 2.5 Transformer 内部：一个巨大的数学函数

### 是什么

Transformer 是现代 LLM 的核心架构，主要由以下部分组成：

- **Embedding**：把每个 token 映射成向量；
- **Attention**：让不同位置的 token 交换信息；
- **MLP**：对每个位置做非线性变换；
- **Layer Norm、残差连接**等；
- 最后输出 **logits**，再经 **softmax** 变成概率。

### 为什么重要

- 它把输入 token 序列映射为下一个 token 的概率分布。
- 它是**无状态函数**：没有生物神经元那样的记忆，所有“记忆”都在参数和当前上下文中。
- 它的表达能力、可优化性、并行性，使它适合大规模 GPU 训练。

### Karpathy 的例子

- 他用一个 3D Transformer 可视化网站展示前向传播：token 先变成向量，然后经过 attention、MLP 等模块，最后输出概率。
- 可视化模型约有 **85,000 个参数**，只是为了便于观察；真实生产模型有数十亿到数千亿参数。
- 他强调：不要把人工神经元过度类比为生物神经元；它们只是简单的数学运算。

## 2.6 Inference：逐 token 采样

### 是什么

Inference 是使用训练好的固定参数生成新 token 的过程：

1. 输入一段前缀；
2. 模型输出下一个 token 的概率分布；
3. 按概率采样一个 token；
4. 把它追加到序列末尾；
5. 重复上述过程。

### 为什么重要

- ChatGPT 与你的对话本质上就是 inference，**不会更新模型参数**。
- 因为采样是随机的，同一个 prompt 每次可能得到不同回答。
- 模型不是在“复读训练数据”，而是在生成统计上相似、但可能全新的 token 序列。

### Karpathy 的例子

- 输入 token `91`，模型可能采样出 `860`，再采样出 `287`，继续生成。
- 同一段上下文有时会生成与训练文档相同的片段，有时会“跑偏”到训练集中没有的原句。
- 他把 base model 的生成称为“dreaming internet pages”：它会做梦一样生成互联网风格文本。

## 2.7 GPT-2：第一个“可识别的现代 LLM 堆栈”

### 是什么

GPT-2 是 OpenAI 2019 年发布的模型，是第一个在架构和训练方式上与现代 LLM 高度相似的模型。

### 为什么重要

它证明了“Transformer + 大规模互联网文本 + next-token prediction”这条路线可行；现代模型只是把同样的配方做得更大、更快、更便宜。

### 关键数字

|项目|GPT-2 数值|
|---|---|
|参数量|约 1.5–1.6B|
|上下文长度|1,024 tokens|
|训练 token 数|约 100B tokens|
|2019 年估计训练成本|约 4 万美元|
|Karpathy 复现成本|约 1 天、600 美元；优化后可更低|
|复现训练量|32,000 步 × 1M tokens ≈ 33B tokens|
|硬件|8×NVIDIA H100|
|每步耗时|约 7 秒|

### Karpathy 的演示

- 他现场展示 GPT-2 训练日志：每条线是一次参数更新，loss 持续下降。
- 训练初期模型输出完全是乱码；训练到 1% 时已有局部连贯性；完整训练后能生成较连贯的英文。
- 推理每 20 步运行一次，可以看到模型从“随机噪声”逐渐变成“会写英文”。
- 他租用 8×H100 节点，按每 GPU 每小时 3 美元计算，一天约 600 美元。

### 核心结论

- 训练的本质是“让预测概率与训练数据统计规律一致”。
- 算力、数据和软件优化共同推动了成本下降。
- 今天的大模型训练需要成千上万甚至十万级 GPU 的数据中心。

## 2.8 Llama 3.1 Base Model：模型到底学到了什么？

### 是什么

Llama 3.1 是 Meta 发布的开源权重模型系列，最大版本约 **405B 参数**，预训练约 **15T tokens**。Karpathy 用它的 **base model**（不是 instruct/assistant 版本）做演示。

### 为什么重要

Base model 展示了预训练的“原始产物”：它有大量知识和语言能力，但**还不是助手**。

### Karpathy 的具体演示

#### 1. Base model 不会自动当助手

输入：

> What is 2 + 2?

Base model 不会回答“4，还有什么可以帮你？”，而是把这句话当成互联网文本的前缀，继续生成哲学讨论或其他内容。  
它只是“非常昂贵的自动补全”。

#### 2. 同一 prompt，多次生成不同答案

因为每次都在采样，base model 对同一前缀可能给出完全不同的续写。这说明它是**随机系统**。

#### 3. 知识是“模糊回忆”，不是精确数据库

他让模型续写“巴黎必看地标 top 10”。模型能列出一些合理景点，但信息是概率性的；越常见的内容越可能记得准确，越冷门的内容越不可靠。

#### 4. 模型会逐字背诵训练数据

他粘贴维基百科“斑马”的第一句话，模型能大段逐字复述维基百科内容。  
这被称为 **regurgitation（复读/ regurgitation）**。原因是高质量来源（如维基百科）可能在训练中被重复采样多次，模型因此记住了原文。

#### 5. 知识截止日期之后，模型会编造“平行宇宙”

Llama 3.1 的知识截止到 2023 年底。Karpathy 让它续写 2024 年美国大选：

- 第一次生成：特朗普的竞选搭档是 Mike Pence，对手是 Hillary Clinton / Tim Kaine；
- 第二次生成：竞选搭档是 Ron DeSantis，对手是 Joe Biden / Kamala Harris。

这些都是模型基于旧知识做出的“合理猜测”，也就是**幻觉**。

#### 6. In-context learning / few-shot prompting

他给模型 10 组“英语单词 → 韩语翻译”的例子，然后让它翻译 `teacher`。模型能正确输出韩语翻译。  
这说明 base model 可以在上下文中“临时学会”一个模式，不需要更新参数。

#### 7. 用 prompt 临时“召唤”助手人格

他构造一个看起来像网页对话的 prompt：

> Here is a conversation between an AI assistant and a human...

然后问“为什么天空是蓝色的？”，模型会以助手口吻回答“瑞利散射”。  
但这并不可靠：它还会继续编造下一轮人类问题。  
这说明 SFT 的必要性——只靠 prompt 可以临时模拟助手，但不能稳定地变成助手。

### 核心结论

> Base model 是“互联网文档模拟器”，是互联网的**有损压缩**。  
> 它有知识、有语言能力、有 in-context learning，但没有稳定的助手人格、没有可靠的事实核查、没有“知道自己不知道”的能力。

# 3. SFT：把互联网模拟器变成助手

## 3.1 SFT 是什么

### 是什么

**SFT（Supervised Fine-Tuning，监督微调）** 是在 base model 上继续训练，但把数据从“互联网文档”换成“人类编写的对话”。

算法与预训练几乎相同，仍然是 next-token prediction；变化的只是数据分布。

### 为什么重要

- 预训练模型只会“续写互联网文本”；
- SFT 教会它“用户提问 → 助手回答”的格式、人格、拒绝行为、工具调用方式；
- 它是把 base model 变成 ChatGPT 的关键一步。

### Karpathy 的例子

- 预训练可能需要数月、成千上万台机器；
- SFT 可能只需要数小时（相对而言），因为对话数据量小得多；
- 但 SFT 的数据质量极其重要。

---

## 3.2 SFT 数据：人类标注员的“理想回答”

### 是什么

SFT 数据通常是多轮对话：

- 用户写一个 prompt；
- 人类标注员写出“理想助手回复”；
- 有时还有多轮追问和回答；
- 也可能包含拒绝回答、工具调用、人格设定等。

### 为什么重要

模型通过**模仿**这些对话来学习“助手应该怎样说话”。这是一种“用示例编程”。

### Karpathy 的例子

- 他引用 OpenAI 2022 年的 **InstructGPT** 论文。
- 标注员来自 Upwork、Scale AI 等外包平台。
- 标注员先自己想 prompt，例如：
    - “列出 5 个重新找回职业热情的方法”
    - “接下来该读的 10 本科幻小说”
    - “把这句话翻译成西班牙语”
- 然后他们写出理想助手回复。
- 公司会给标注员数百页的标注指南，核心原则是：
    - **Helpful（有帮助）**
    - **Truthful（真实）**
    - **Harmless（无害）**
- InstructGPT 数据集没有公开；OpenAssistant 等开源项目做了类似尝试。
- OpenAssistant 例子：用户问“monopsony（买方垄断）在经济学中的意义，请举例”，标注员写出回答；下一轮用户说“把它解释给一只狗听”，标注员再写更简单的版本。
- 现代 SFT 数据集可能有**数百万条对话**，很多是 LLM 合成、人类编辑的混合数据，例如 UltraChat。
- 代码等专业领域会雇佣更专业的标注员。

### 核心结论

> SFT 不是“写规则”，而是“写大量示例，让模型统计性地模仿”。  
> 你拿到的回答，本质上是“某个被雇佣的人类标注员在类似情境下会怎么写”的神经网络模拟。

---

## 3.3 对话如何变成 token：Chat Template 与特殊 token

### 是什么

对话是结构化对象（用户、助手、轮次），需要被编码成一维 token 序列。不同模型使用不同的 **chat template**。

### 为什么重要

- 模型必须知道“谁在说话”“一轮什么时候结束”；
- 特殊 token 是训练时新加入的符号，不是普通文本；
- 这些格式决定了模型如何区分 system、user、assistant。

### Karpathy 的例子

一个两轮对话可能被编码成类似：

```
<|im_start|>user
What is 2+2?<|im_end|>
<|im_start|>assistant
2+2 is 4.<|im_end|>
<|im_start|>user
What if it was times?<|im_end|>
<|im_start|>assistant
```

- `<|im_start|>`、`<|im_end|>` 是特殊 token；
- 这个例子中的对话最终约 **49 个 token**；
- `im_start` 中的 “im” 据说是 “imaginary monologue” 的缩写，但 Karpathy 也表示自己不确定命名由来；
- 具体协议不重要，重要的是：**对话最终仍然只是 token 序列**。

### 核心结论

SFT 没有改变 Transformer 的本质，只是把“对话结构”编码进 token 序列，然后继续做 next-token prediction。

---

## 3.4 SFT 学到了什么：助手人格、格式与拒绝

### 是什么

SFT 让模型学会：

- 以助手身份回答；
- 遵循指令；
- 保持礼貌、有帮助的语气；
- 在敏感问题上拒绝；
- 使用特定格式（列表、步骤、引用等）；
- 调用工具；
- 在对话中保持上下文。

### 为什么重要

这些行为不是预训练自然产生的，而是通过人类示范“编程”进去的。

### Karpathy 的例子

- 问“巴黎 top 5 地标”，模型会给出一个看起来像人类标注员写过的列表。
- 如果这个问题恰好出现在 SFT 数据中，回答可能非常接近标注员原文；
- 如果没出现过，模型会结合预训练知识和 SFT 人格，生成“类似风格”的答案。
- 标注员可能花 20 分钟上网查资料，然后写出答案；模型学到的是这种“研究后写答案”的行为模式。

### 重要限制

- SFT 模型可能复述训练答案，也可能只是“相似风格”；
- 它不能覆盖测试时所有可能的 prompt；
- 它本质上仍是**模仿**，不是真正理解或验证。

---

## 3.5 SFT 的局限：为什么需要 RL？

### 是什么

SFT 是“模仿人类专家/标注员的答案”。但人类标注员并不知道**对 LLM 来说最优的 token 序列**是什么。

### 为什么重要

这是从 SFT 过渡到 RL 的关键。

### Karpathy 的例子

同一道题：

> Emily 买了 3 个苹果和 2 个橙子，每个橙子 2 美元，总价 13 美元，每个苹果多少钱？

有四种都得到答案 3 的解法：

1. 直接跳到答案；
2. 设方程；
3. 用英文逐步解释；
4. 省略中间步骤。

人类标注员不知道哪一种对模型最好：

- 太短的解法要求模型在单个 token 中完成太多计算；
- 太长的解法可能浪费 token；
- 人类觉得自然的步骤，对模型可能太跳跃；
- 模型知道的某些知识，人类标注员未必知道。

### 核心结论

> SFT 只能把模型“初始化”到正确答案附近；  
> 真正最优的推理路径，必须让模型自己在 RL 中试出来。

---

# 4. 强化学习：从模仿到试错

## 4.1 为什么需要 RL：学校类比

Karpathy 用“上学”类比三个阶段：

|学习阶段|LLM 对应|说明|
|---|---|---|
|读教材的讲解|预训练|建立背景知识|
|看例题和标准解法|SFT|模仿专家解法|
|做课后练习题|RL|只给题目和答案，自己探索解法|

练习题的关键是：

- 你知道最终答案；
- 但没有人给你完整解法；
- 你必须自己尝试、犯错、调整，最终发现能稳定得到答案的路径。

这就是 RL 的核心：**guess and check（猜测与检查）**。

---

## 4.2 RLVR：在可验证领域做强化学习

> 注：Karpathy 在讲座中直接称其为“verifiable domains 上的 RL”；业界常概括为 **RLVR（Reinforcement Learning with Verifiable Rewards）**。

### 是什么

在可验证领域，模型对每个 prompt 生成大量候选解法（rollouts），然后用程序自动判断哪些答案正确，并强化那些导致正确答案的 token 序列。

### 为什么重要

- 不需要人类逐条评分；
- 可以生成成千上万甚至上百万个候选解；
- 模型可以发现自己从未见过的推理策略；
- 这是 DeepSeek-R1、OpenAI o1/o3 等推理模型的核心训练方式。

### Karpathy 的例子

- 对一道数学题，模型生成 15 个解法；
- 其中 4 个得到正确答案，11 个错误；
- 强化正确答案对应的 token 路径；
- 在数万道题、每道题数千个解法的规模上重复；
- 模型逐渐学会“怎样一步步算”比“直接猜答案”更可靠。

### 关键点

- 可验证奖励可以来自：
    - 数学题的 boxed answer；
    - 代码的单元测试；
    - 游戏的胜负；
    - 形式化证明检查器；
    - 有时也用 LLM judge 辅助判断。
- 因为奖励函数不容易被“钻空子”，RL 可以运行很久。

---

## 4.3 DeepSeek-R1：推理能力如何“涌现”

### 是什么

DeepSeek-R1 是 DeepSeek 公开发表的推理模型，展示了 RL 如何让模型在数学等任务上显著提升，并自发出现长链推理行为。

### 为什么重要

它公开了大量 RL 训练细节，让外界第一次较清楚地看到：

- RL 不只是“对齐风格”；
- 它可以真正提升复杂问题求解能力；
- 模型会自发学会回溯、检查、换角度。

### Karpathy 的演示与观察

- 随着 RL 训练步数增加，数学题准确率持续上升；
- 模型的平均回答长度也上升；
- 变长的原因不是“啰嗦”，而是模型学会了**中间思考**：
    - “wait, wait, wait, let me re-evaluate”
    - “let me check my math again”
    - 换一种方法再算一遍
    - 回溯、重试、从不同角度验证
- 这些“内心独白”不是人类标注员硬编码的，而是 RL 过程中涌现出来的；
- 模型最终会先进行内部推理，再写出面向人类的简洁答案。

### 例子：Emily 的苹果题

推理模型会：

1. 设未知数；
2. 计算橙子总价；
3. 求苹果总价；
4. 除以苹果数量；
5. 不放心，再换一种方法验证；
6. 最后给出整洁的最终答案。

Karpathy 说，看这个过程会很难不觉得“模型在思考”。

### 推理模型生态

- DeepSeek-R1 是开放权重模型，采用 MIT 许可证；
- OpenAI 的 o1/o3 系列、Google Gemini 2.0 Flash Thinking 也属于推理模型；
- OpenAI 不在网页界面展示完整 chain-of-thought，只展示摘要，部分原因是担心**蒸馏风险**：别人可以模仿推理轨迹，用较小模型复现大量推理能力；
- 讲座当时 Anthropic 还没有公开的“thinking model”；
- Karpathy 说自己 80–90% 的日常使用仍是 GPT-4o 这类普通模型，只有遇到困难数学/代码问题才用推理模型，因为后者更慢。

---

## 4.4 AlphaGo 的启示：RL 可以超越人类示范

### 是什么

AlphaGo 是 DeepMind 的围棋系统，先用人类棋谱做监督学习，再通过自我对弈和强化学习提升。

### 为什么重要

它证明了：

- **监督学习**模仿人类高手，但通常会在人类水平附近遇到上限；
- **强化学习**可以通过自我对弈，发现人类从未下过的策略，从而超越人类。

### Karpathy 的例子

- AlphaGo 的监督学习版本很强，但很难超过顶尖人类；
- RL 版本通过自我对弈继续提升，最终击败李世石；
- **Move 37**：AlphaGo 下出的一步棋，人类专家评估其出现概率约为 **万分之一**，但事后看非常精彩；
- 这说明 RL 可以让系统**离开人类数据分布**，发现新策略。

### 对 LLM 的启示

- 未来的 LLM 可能发现人类从未想到的类比、推理策略，甚至“自己的思考语言”；
- 但这需要大量、多样、可验证的“练习环境”；
- 如何为所有知识领域构造这样的练习题，是当前 frontier 研究的核心问题之一。

---

## 4.5 RLHF：在不可验证领域使用人类偏好

### 是什么

**RLHF（Reinforcement Learning from Human Feedback）** 用于笑话、诗歌、摘要、文风等没有自动对错标准的任务。

流程：

1. 对同一个 prompt，让模型生成多个候选回答；
2. 让人类标注员给这些回答**排序**（不是直接打精确分数）；
3. 训练一个独立的**奖励模型**，学习人类的排序偏好；
4. 用 RL 优化语言模型，让它的输出获得更高奖励模型分数。

### 为什么重要

- 人类直接写“理想答案”很难，尤其是创意写作；
- 但人类比较“哪个更好”相对容易；
- 这利用了 **discriminator-generator gap（判别器-生成器差距）**：判断比生成容易。

### Karpathy 的例子

- Prompt：“写一个关于鹈鹕的笑话。”
- 模型生成 5 个笑话；
- 人类标注员把它们从最好笑到最不好笑排序；
- 奖励模型输入“prompt + 候选回答”，输出一个 0 到 1 的分数；
- 训练奖励模型，使其分数与人类排序一致；
- 然后让语言模型针对奖励模型做 RL。

### 规模对比

- 如果直接用人类做 RL，可能需要人类评估 **10 亿次**笑话；
- 用奖励模型，只需要人类标注约 **5,000 个**候选回答；
- 之后 RL 可以无限次查询奖励模型。

### 核心问题：奖励模型会被“钻空子”

- 奖励模型是一个巨大的神经网络，不是真正的人类；
- RL 非常擅长寻找对抗样本（adversarial examples）；
- 训练久了，模型会生成人类看来毫无意义、但奖励模型打高分的文本；
- 例如“the the the”可能被奖励模型打出接近 1.0 的分数；
- 把这种样本加回训练集只能修补一个洞，但模型会找到无限多个新洞；
- 因此 RLHF 通常只能训练几百步，然后必须停止并发布模型。

### Karpathy 的核心判断

> **“RLHF is not RL.”**  
> 他的意思是：RLHF 技术上是 RL，但它不是那种可以无限扩展、不断涌现新能力的 RL；它的奖励函数可被 gaming，所以更像一种“偏好微调”，而不是“魔法 RL”。

---

## 4.6 可验证 vs. 不可验证：完整对照

|维度|可验证领域|不可验证领域|
|---|---|---|
|**定义**|答案可自动判定对错|没有唯一答案，需要人类判断|
|**例子**|数学、代码、围棋、形式逻辑|笑话、诗歌、摘要、文风、建议|
|**奖励来源**|答案匹配、单元测试、胜负|人类排序 → 奖励模型|
|**训练方法**|RLVR|RLHF|
|**SFT 的作用**|提供专家解法，初始化模型|提供理想回复，塑造人格与风格|
|**能否长期训练**|可以，奖励不易被 gaming|通常不行，奖励模型会被 gaming|
|**能力来源**|模型自己试错、发现策略|模仿/对齐人类偏好|
|**主要风险**|题目分布、验证器漏洞|奖励模型失真、谄媚、作弊|
|**典型结果**|推理模型、数学/代码能力提升|更有帮助、更符合人类风格|

### 关键结论

- **RLVR 让模型“发现怎么想”**；
- **RLHF 让模型“更像人类喜欢的样子”**；
- **SFT 让模型“学会像助手一样说话”**；
- 从可验证领域到不可验证领域的迁移，仍是开放问题。

# 5. LLM 心理学：七个必须理解的现象

> Karpathy 用“LLM psychology”形容这些不是 bug、而是训练管线自然产生的认知特征。

## 5.1 总览表

|现象|是什么|为什么发生|Karpathy 的例子|实践启示|
|---|---|---|---|---|
|**幻觉 Hallucination**|编造看似合理但错误的信息|训练数据中“谁是谁”总是被自信回答；模型模仿答案格式，而不是核查事实|Falcon 7B 对虚构人物“Orson Kovats”编出三种身份|用检索/工具；允许“我不知道”；不要把参数记忆当数据库|
|**工具使用 Tool use**|通过特殊 token 调用搜索、Python 等外部程序|模型本身不会算数、不能上网、没有持久记忆|`search_start ... search_end` 调用 Bing；`use code` 调 Python|明确要求使用工具；检查工具调用结果|
|**工作记忆 Working memory**|上下文窗口中的 token 是模型可直接访问的“内存”|参数是模糊长期记忆，上下文是短期工作记忆|让模型总结《傲慢与偏见》第一章，直接粘贴原文效果更好|把关键资料放进上下文；不要依赖模型回忆|
|**自我认知 Self-awareness**|模型没有持久自我，每次对话重启|身份由 SFT 数据和 system message 塑造|Falcon 自称 OpenAI/GPT-3；OLMo 用 240 条身份对话硬编码|不要把模型自述当作事实；用 system prompt 设定身份|
|**Token 与思考**|每个 token 只有有限计算，复杂推理要写成多个 token|Transformer 层数有限，单次前向计算量小|Emily 苹果题；23/177 题单 token 答错；数 177 个点答成 161|让模型分步思考；要求中间结果；用代码/工具|
|**拼写问题**|模型看 token，不看字符|Tokenization 把多个字符打包成一个符号|`ubiquitous` 是 3 个 token；`strawberry` 的 r 数量|字符任务交给 Python；不要依赖模型逐字操作|
|**智能不均匀 Jagged intelligence**|能力像“瑞士奶酪”，有大量洞|训练分布、tokenization、计算限制、未知内部特征共同导致|会解奥赛/博士题，却可能答错 9.11 与 9.9 的大小|把模型当工具；交叉验证；不要盲目信任|

## 5.2 幻觉：为什么模型会“自信地编”

### 是什么

模型生成与事实不符、但语气自信的内容。

### 为什么发生

- 训练数据中的问答通常是“问谁是谁 → 自信回答”；
- 模型学到的是**答案的格式和风格**，不是“我是否知道”；
- 模型内部可能有“不确定”信号，但没有被连接到“说不知道”的输出；
- 模型没有互联网访问，也没有内置事实数据库。

### Karpathy 的例子

- 他让 Falcon 7B 回答“Orson Kovats 是谁”；
- 模型先说他是美国科幻作家，再说他是 1950 年代电视剧角色，又说他是前小联盟棒球运动员；
- 每次答案都不同，因为它在采样，而不是在检索；
- ChatGPT 在禁用工具后，也可能编造；启用搜索后会说“我不知道这个人”。

### 缓解方法

1. **训练“我不知道”数据**：
    - Meta 在 Llama 3 中从文档生成问题；
    - 多次询问模型，比较答案与正确答案；
    - 如果模型不知道，就把“我不知道”加入 SFT 数据；
    - 例子：Dominik Hašek 赢过几次斯坦利杯？模型说 4 次或 0 次，正确答案是 2 次；于是加入“我不知道”样本。
2. **工具/检索**：
    - 让模型搜索网页，把结果放进上下文；
    - 例子：ChatGPT 搜索“Orson Kovats”，找到来源后给出更可靠的回答；
    - 关键：**上下文中的信息比参数记忆更可信**。

### 重要提醒

> 微调不会消除幻觉；它只是把“互联网梦”引导成“助手梦”。  
> 只要模型在凭记忆回答，就要保持警惕。

---

## 5.3 工具使用：特殊 token 如何调用外部世界

### 是什么

模型生成特殊 token，触发外部程序；程序执行后把结果放回上下文，模型继续生成。

### 为什么重要

模型本身：

- 不会精确算术；
- 不能上网；
- 没有持久记忆；
- 不能可靠地逐字符操作。

工具可以弥补这些短板。

### Karpathy 的例子

#### Web Search

模型输出：

```
<|search_start|> query <|search_end|>
```

推理程序检测到 `search_end` 后：

1. 暂停生成；
2. 打开 Bing/Google；
3. 输入查询；
4. 把返回文本粘贴进上下文；
5. 模型继续生成，并引用来源。

#### Code Interpreter

用户说“use code”，模型写出 Python 程序，外部解释器执行，结果返回上下文。  
例子：计算苹果价格；数 177 个点；处理 `ubiquitous` 的字符。

### 关键点

- 工具调用能力也是通过 SFT 示例教出来的；
- 模型在预训练中已经理解“搜索”“代码”是什么，所以少量示例就能学会使用；
- 模型可以决定何时使用工具，也可以被要求“不要用工具”。

---

## 5.4 工作记忆：参数是回忆，上下文是内存

### 是什么

- **参数中的知识**：长期、模糊、概率性的回忆；
- **上下文窗口中的 token**：短期、可直接访问的工作记忆。

### 为什么重要

这决定了你该如何写 prompt：

- 让模型“回忆”某本书，效果取决于它见过多少；
- 把原文放进上下文，模型就能直接处理，质量更高。

### Karpathy 的例子

- 让 ChatGPT 总结《傲慢与偏见》第一章，它能给出合理摘要，因为它对这本名著有大量记忆；
- 但如果把第一章原文粘贴进上下文，再让它总结，结果会显著更好；
- 因为模型不需要“回忆”，它可以直接读取。

### 实践启示

> 重要资料不要只给标题，要贴原文/数据/代码。  
> 上下文是模型的工作内存，不是无限硬盘。

---

## 5.5 自我认知：模型没有“自我”

### 是什么

模型没有持久存在、没有连续意识、没有真正的“自我”。每次对话都是重新启动：

- 加载固定参数；
- 建立上下文；
- 生成 token；
- 对话结束，上下文删除。

### 为什么重要

问“你是谁”“谁训练了你”并不是在询问一个真实主体的自传，而是在触发训练数据中的统计模式。

### Karpathy 的例子

- Falcon 7B 自称“由 OpenAI 基于 GPT-3 构建”，但这很可能是幻觉，因为互联网上大量文本都在谈论 ChatGPT/OpenAI；
- OLMo 2 的 SFT 数据中有 **100 万条对话**，其中 **240 条**是硬编码的身份对话：
    - “告诉我关于你自己”
    - “我是 OLMo，由 Allen Institute for AI 开发……”
- 另一种方式是通过 **system message** 设定身份，例如：
    
    > You are ChatGPT, a model developed by OpenAI...
    
- 你在 ChatGPT 界面看到的是空白对话，但系统消息其实隐藏在上下文里。

### 核心结论

> 模型的“自我”是数据、system prompt 和采样共同构造出来的角色，不是持久的心灵。

---

## 5.6 Token 与思考：为什么模型需要“打草稿”

### 是什么

Transformer 每个 token 的前向计算量有限；模型不能在单个 token 中完成任意复杂的推理。

### 为什么重要

- 复杂问题必须拆成多个 token；
- 中间步骤是模型的“草稿纸”；
- 要求模型“直接给答案”会迫使它在单个 token 中完成过多计算，容易出错。

### Karpathy 的例子

#### Emily 苹果题

- 直接输出“答案是 3”要求模型在一个 token 中完成全部计算；
- 分步写“橙子总价 4 美元，13−4=9，9÷3=3”则每一步都很简单；
- 因此，训练数据中“好的解法”应该是分步的，而不是直接跳答案。

#### 更难的版本

- 23 个苹果、177 个橙子；
- 要求单 token 回答时，模型答 5，正确答案是 7；
- 允许逐步计算后，模型能正确得到 7。

#### 数点

- 输入 177 个点，问“有多少个点”；
- 模型回答 161；
- 因为 tokenization 把多个点打包成一个 token，模型无法逐字符数；
- 让它用 Python，`len()` 或 `count()` 得到 177。

### 核心结论

> **Models need tokens to think.**  
> 复杂推理需要 token 预算；不要要求模型在单个 token 里完成太多事情。

---

## 5.7 拼写问题：Tokenization 的副作用

### 是什么

模型看到的是 token，不是字符；因此逐字符任务（拼写、反转、数某个字母）很容易失败。

### 为什么重要

这解释了为什么模型能写代码、解数学题，却可能数错 `strawberry` 里的 r。

### Karpathy 的例子

- `ubiquitous` 在 tokenizer 中是 3 个 token；
- 要求“从第一个字符开始，每第三个字符取一个”，模型失败；
- 原因是它看不到单个字符，只能看到 token 块；
- 让模型“use code”，Python 可以精确索引字符；
- `strawberry` 里有 3 个 r；早期模型坚持说 2 个，后来才修好；
- 这是“看不到字符”+“不会数数”两个问题叠加。

### 实践启示

> 字符级任务、精确计数、字符串操作，优先让模型写代码，而不是“心算”。

---

## 5.8 智能不均匀：瑞士奶酪模型

### 是什么

模型的能力不是均匀的；它在某些领域超强，在某些简单任务上却会突然失败。

### 为什么重要

不能因为模型能解奥赛题，就假设它不会在简单问题上犯错。

### Karpathy 的例子

- 问：9.11 和 9.9 哪个大？
- 模型有时说 9.11 更大，并给出看似合理的错误解释；有时又会自我纠正；结果不稳定；
- 但它同时能回答奥赛级数学、博士级物理/化学/生物问题；
- 他提到一个研究观察：模型内部某些与“圣经经文”相关的特征会被激活，因为 9.11 看起来像经文编号 9:11，而在经文排序中 9:11 确实在 9:9 之后；这可能是干扰来源之一，但并未完全解释；
- 他把这种现象称为“Swiss cheese model”：能力像瑞士奶酪，大部分地方很强，但随机分布着洞。

### 实践启示

> 把 LLM 当作“能力很强但会随机犯错的工具”，而不是“全知专家”。

# 6. 未来趋势与实践建议

## 6.1 Karpathy 预判的未来方向

### 1. 多模态

- 模型将原生处理文本、音频、图像；
- 音频可以按频谱切片 token 化；
- 图像可以按 patch token 化；
- 本质上仍是“token 序列 + next-token prediction”，只是 token 类型更多。

### 2. Agent（智能体）

- 当前模型大多只完成单个短任务；
- 未来会出现能长时间运行、调用工具、纠错、定期汇报的 agent；
- 人类角色从“操作者”变成“监督者”；
- 可能出现“人类-to-agent 比例”的概念，类似工厂中的人机比例。

### 3. 计算机使用

- 模型可以直接控制键盘、鼠标，替你操作软件；
- ChatGPT Operator 是早期例子。

### 4. Test-time training / 持续学习

- 当前模型部署后参数固定，只能通过上下文学习；
- 人类会在睡眠中更新“参数”；
- 未来需要让模型在部署后继续学习，尤其是长时多模态任务；
- 仅靠加长 context window 可能不够。

---

## 6.2 使用 LLM 的实用原则

1. **事实性问题**：优先使用搜索/检索，把来源放进上下文；不要只依赖模型记忆。
2. **数学/代码**：要求分步；要求使用代码解释器；检查中间结果和最终结果。
3. **字符/计数任务**：让模型写 Python，不要心算。
4. **长文档**：直接粘贴原文或检索相关段落，不要只说“请总结某本书”。
5. **困难推理**：使用 thinking/reasoning 模型；简单任务不必用，避免不必要等待。
6. **开放创作**：模型可以给初稿和灵感，但最终判断由你负责。
7. **永远验证**：模型会幻觉、会跳过步骤、会随机犯错；把它当工具，而不是权威。

> Karpathy 的总结：  
> **“Use them as tools in a toolbox, check their work, and own the product of your work.”**

# 7. 关键术语速查表

|术语|一句话解释|
|---|---|
|**LLM**|用海量文本训练、通过逐 token 预测下一个 token 来生成语言的神经网络。|
|**Token**|模型处理文本的基本单位，可能是一个词、词的一部分、空格或标点。|
|**Tokenizer**|把文本编码成 token ID、再解码回文本的程序。|
|**BPE**|通过反复合并高频相邻符号来构建 token 词表的算法。|
|**Vocabulary**|模型可使用的全部 token 集合，GPT-4 例子约 100,277 个。|
|**Embedding**|把每个 token 映射成向量的表示层。|
|**Transformer**|由 attention、MLP 等模块堆叠而成、用于序列建模的神经网络架构。|
|**Attention**|让序列中不同位置相互交换信息的机制。|
|**MLP**|Transformer 中对每个位置做非线性变换的前馈网络。|
|**Logits**|模型输出的未归一化分数，经 softmax 后变成概率。|
|**Softmax**|把一组分数转换成概率分布的函数。|
|**Context window**|模型一次能看到的 token 范围，相当于工作记忆。|
|**Inference**|使用固定参数生成 token 的过程，不更新模型权重。|
|**Sampling**|按模型输出的概率分布随机选择下一个 token。|
|**Base model**|只经过预训练、会续写互联网文本但还不是助手的模型。|
|**Pre-training**|在海量互联网文本上做 next-token prediction 的训练阶段。|
|**Post-training**|预训练之后的 SFT、RLHF、RLVR 等阶段的总称。|
|**SFT**|用人类/合成对话示范继续训练模型，使其学会助手行为。|
|**Chat template**|把多轮对话编码成 token 序列的格式规范。|
|**Special token**|用于标记角色、轮次、工具调用等控制信息的非普通文本 token。|
|**Labeler**|编写理想回答或给模型回答排序的人类标注员。|
|**RLHF**|用人类偏好训练奖励模型，再用 RL 优化语言模型的方法。|
|**Reward model**|输入 prompt 和回答、输出一个偏好分数的神经网络。|
|**RLVR**|使用可自动验证的奖励（答案、测试、胜负）做强化学习。|
|**Rollout**|模型针对一个 prompt 采样出的一条候选解法。|
|**Verifiable domain**|答案可被程序或规则自动判定对错的领域，如数学、代码。|
|**Unverifiable domain**|没有唯一正确答案、依赖人类判断的领域，如笑话、诗歌。|
|**Chain of thought**|模型在给出最终答案前生成的一系列中间推理 token。|
|**Reasoning model**|经过 RL 训练、会花较多 token 进行内部思考的模型。|
|**Distillation**|用大模型的输出或推理轨迹训练较小模型，以迁移能力。|
|**Hallucination**|模型自信地生成与事实不符的内容。|
|**Working memory**|上下文窗口中的 token，模型可以直接访问和处理。|
|**Tool use**|模型通过特殊 token 调用搜索、代码解释器等外部工具。|
|**In-context learning**|模型不更新参数、仅凭 prompt 中的示例临时学会模式。|
|**Few-shot prompting**|在 prompt 中给少量示例，让模型模仿完成任务。|
|**Regurgitation**|模型逐字复述训练数据中的内容。|
|**Knowledge cutoff**|模型预训练数据覆盖的时间截止点。|
|**Test-time training**|在部署/推理阶段继续更新模型能力的研究方向，目前尚未成为标准做法。|
|**Agent**|能长时间运行、调用工具、执行多步任务并接受监督的模型系统。|
|**Multimodal**|同时处理文本、音频、图像等多种 token 的模型能力。|
|**Jagged intelligence**|模型能力不均匀，某些方面极强、某些简单任务却会失败。|
|**Reward hacking**|模型找到奖励函数的漏洞，用无意义输出骗取高分。|
|**Discriminator-generator gap**|人类判断哪个答案更好，通常比直接生成理想答案更容易。|
|**Loss**|衡量模型预测与真实下一个 token 差距的标量，越低越好。|
|**Parameters / Weights**|神经网络中通过训练学到的数值，承载模型知识。|

## 最后一张“总图”

```
互联网文本
   │  清洗、去重、去 PII
   ▼
Token 序列（约 15T tokens）
   │  预训练：next-token prediction
   ▼
Base Model（互联网文档模拟器）
   │  SFT：人类对话示范
   ▼
Assistant Model（助手人格、格式、拒绝、工具用法）
   │
   ├── 可验证领域：RLVR
   │     数学、代码、游戏
   │     自动奖励 → 大量试错 → 发现推理策略
   │     → Reasoning Model
   │
   └── 不可验证领域：RLHF
         笑话、诗歌、摘要、文风
         人类排序 → 奖励模型 → RL
         奖励可被 gaming → 只能短时间训练
         → Aligned Assistant
```

> **一句话收束：**  
> LLM 是一个“有损压缩互联网 + 模仿人类标注员 + 在可验证环境中试错学习”的统计系统。  
> 它很强，但不是全知；会用工具、会写草稿、会验证，才是正确用法。
